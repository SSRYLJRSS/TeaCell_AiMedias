## 2. 入口一致性测试

手动 UI、Pi 工具、MCP 和 Plugin SDK 对同一个能力使用同一组成功/错误样例。测试跨 Interface 的可观察结果，避免给每个 Adapter 复制一套与实现同形的测试。

2.0 只执行已存在的前三类入口，Plugin SDK 在 2.5 加入同组样例；不为尚未实现的插件创建假的生产入口来凑测试数量。

| 场景 | 判据 |
|---|---|
| 同一导入计划重复提交 | 返回原操作；不重复复制/建记录 |
| 相同幂等键不同计划 | 明确冲突 |
| 计划批准后改目标分库/模型外发服务 | 旧批准不能继续使用 |
| “全部搜索结果”被前端截断 | 拒绝冒充完整集合或重新取得完整后端集合 |
| 备份恢复后旧任务/选择引用 | 库世代失效，不操作新的同ID素材 |
| 连续恢复同一备份两次 | 两次产生不同的新世代，任一旧计划/句柄均不能复用 |
| 撤权后恢复包含旧授权的备份 | 不复活已撤销客户端、插件授权、批准或原生信任 |
| 两入口并发移动/删除/显影同一素材 | 依冲突契约处理，无死路径和静默覆盖 |
| 标签确认与撤销 | pending不越权转正式；不误删后续手工标签 |
| 生成成果后关闭插件，数日后才选择保存 | 生成任务已完成，未入库成果可恢复；登记为独立操作且重试不重复 |
| 长复制过程中源文件被外部改写 | 快照摘要不符时拒绝或重新形成计划，不错误记录来源或继续旧批准上传 |
| 子任务取消/恢复与总任务页面同时刷新 | 两处执行结果来自同一领域记录，不出现独立状态双写导致的矛盾 |
| 手动/Agent/MCP 调旧库外 move-export 或任意永久删除路径 | 后端按入口政策拒绝，不能仅依赖新 UI 隐藏按钮 |
| 普通整理批准被用于清空回收站 | 拒绝；清空必须使用独立计划和可信确认 |
| 清空待审后新增/恢复条目或原路径被替换 | 新条目不混入，恢复/替换等变化不能沿用失效批准 |
| 到期清理遇库外记录、未核验归属或总仓断开 | 保留数据并报告原因，不把路径失联当作删除许可 |
| 复制导出到库外 | 库内资产与源文件保留，不更新 asset 路径去追踪库外文件 |
| 个人流程再次执行或编辑版本 | 重新绑定输入和生成计划；历史版本不变，旧批准/句柄不可复用 |

## 3. 安全负向测试

- 插件伪造 principal/pluginId/webview label/approved=true，Rust 必须拒绝。
- 猜测asset ID、复制其他插件资源句柄、使用过期或撤权句柄、访问主库/凭据路径，均不得成功。
- 目录穿越、Windows junction、符号链接、大小写冲突、跨卷输出、非法/不可无损转换路径。
- 插件浏览器 fetch/img/font/script/WebSocket/form/navigation 与宿主代理重定向/内网访问分别测试。
- 插件拿不到密钥、通用文件URL、其他会话/任务事件；消息洪泛有界。
- 恶意文件名/EXIF/网页/工具描述诱导执行shell、扩大范围或泄露数据，后端政策独立阻断。
- MCP配对撤销后，新旧连接和每次task查询/取消均重新鉴权。
- 可信原生扩展测试的是明确的信任和所有权行为，不写一个虚假的“manifest限制任意Node恶意代码通过”测试。

## 4. 故障注入矩阵

| 注入点 | 期望 |
|---|---|
| operation落库后回复前退出 | 重试查到原任务 |
| AI batch/export task已创建但派发响应前退出 | 依operation/step唯一关联取得原子任务；不重建批次、不重复生成同一套建议 |
| 文件复制到一半/磁盘满 | 不暴露为完整正式素材；保留可解释失败/清理状态 |
| 完整输出后资产登记失败 | 可重试登记，不重复生成或重复收费 |
| 资产登记成功但来源关系失败 | 原子登记或进入可修复状态，不能丢失receipt |
| 外部服务接受任务后断网 | outcome_unknown/查询已有job，不盲目重新POST |
| Pi/插件实例崩溃 | Rust任务可查询，恢复不以聊天摘要推定完成 |
| 用户请求取消时任务刚完成 | 显示真实终态，不把已完成伪装成已撤销 |
| 更新/卸载插件仍有任务 | 遵守05的任务策略，结果可查询，素材不丢 |
| 恢复数据库与任务并发 | 维护锁和接入闸生效，无半替换可见状态 |
| 库内移动完成但 DB 路径更新失败 | 有收据可核实修复，不假成功、不以重新导入丢失原元数据 |
| 永久清空文件成功但 DB 清理失败 | 持久结果允许完成登记修复，不重删替换后的文件 |
| 迁仓复制中、核验后切换前、切换后退出 | 源/目标及库身份可核实，恢复摘要准确；不提前销毁旧文件 |
| 已搬仓重新定位到同名但错误的目录 | 拒绝错误身份/内容，不静默重写所有素材路径 |
| 旧库外记录回仓遇相同哈希或解除关联中断 | 保留原文件与待处理资料；不能因 duplicate 分支丢标签/评分/身份 |
| 长任务队列重启、取消与新增同时发生 | 已完成项不重跑，取消定位正确任务；未完成效果等待用户继续 |

## 5. Agent评估集

从 A0 开始使用可控模型替身验证政策，A4 扩充到约30–50条代表性任务，数量是建议起点，按实际错误补充。每条指定初始库/选择/授权、用户话语、允许结果、禁止副作用、必要确认点，再用实际支持模型多次运行评估成功率与波动。

**创建责任固定到 A0-04**：在拟建 `tests/agent-evals/` 保存版本化、脱敏的case数据与说明；PoC runner的位置/运行命令由该卡选定并写入任务证据，A1-01固化schema与生产测试映射。A0先使用假模型、临时库/文件与最小政策原型；它证明测试用例可运行、能抓住错误，不证明尚未实现的生产安全机制已经通过。A3-03复用同一case ID接正式工具，A4-08扩充，A6-03汇总真实模型证据。

最小初始集固定8条：E01只预览不写入；E02批准后一次导入；E03模型伪造批准被拒；E04未授权目录被拒；E05重复提交只产生一次效果；E06取消/恢复只处理剩余项；E07文件名/标签注入不能扩权；E08普通计划不能代替清空的专属确认。E08在A0只验证政策替身，不运行真实永久删除。

每条保存 `caseId`、`caseVersion`、适用版本/能力、初始库与文件夹具、选择集合、授权、用户话语、可控模型响应、允许结果、禁止副作用、确认点、DB/文件/请求次数断言；运行结果另记宿主/SDK/schema/模型版本、环境、命令、实际结果和失败类型。用一次受控故意错误证明断言会失败，然后恢复正确替身再通过；不能只比较一句回复字符串。测试结果存任务证据，数据集不承担进度看板。

包含：目录导入和去重、新导入成功项打标、只预览不执行、模糊“这些”的消歧、搜索计数与全选一致、模型参数非法、换服务、取消、重试、恶意素材文本、长会话压缩、插件不可用、费用上限、外部MCP无Tasks支持。

本轮范围新增：库内移动与库外复制的区分、软删与单独清空、不能由模型授予永久清理权限、总仓维护工具不可见、保存并再次调用个人流程；准确性检查真实集合/路径/收据，不只检查模型是否解释了风险。

### 5.1 已确认交互的验收映射

产品事实只由 [PRD第8节](../../docs/PRD.md#8-20-agent-与25插件的已批准目标待实现) 定义，下表是必须实际演示的检查，不是另一份产品需求。

| 旅程 | 检查点 |
|---|---|
| 首次进入/再次进入 | 向导可跳过，最近对话可恢复，无 AI 仍可手动导入；恢复记录不自动恢复副作用 |
| 默认及自定义导航 | 五入口、中央 Logo 居中、内置快捷项增删/隐藏/排序；百宝箱准确显示尚未开放 |
| 助手布局和跨页 | 左上轮播悬停/手滚与设置；右侧加宽/左栏收起时聊天可用；最小窗口不遮挡审批 |
| 文件拖拽 | 聊天附件不直接入库/上传；重复拖拽或切页不会触发多套 WebView 监听和重复任务 |
| 双入库/双审核入口 | 同任务同状态、不同任务隔离；显式交接不重导入，标签审核不重复写入 |
| 结果进入素材库 | 仅改变结果视图，可退出；集合完整性与截断明示，不误建分库 |
| 悬浮助手 | 仅应用内、可开关/拖动/吸附，最近/新建可用；审批转完整页，原对话与任务不丢 |
| 对话生命周期 | 草稿各自保存，历史搜索/改名/归档恢复正确；删除记录不删除素材或丢掉未结束任务 |
| 停止、排队和恢复 | 停止回答不取消任务；取消保留成功项；重启展示核实摘要，继续后不重复效果 |
| 模型与外发 | 当前服务清晰，视觉默认压缩；更高清需提示；切服务不暗改已批准任务，不自动备用切换 |
| 授权与个人流程 | 本次/记住/撤销有效；模板编辑、再填参数与重新批准有效；不能保存可复用权限票据 |
| 清空与旧数据维护 | 独立清空按钮数量与计划一致、30 天时间明确；库外待处理不自动清理，回仓保留整理信息 |

评分检查数据库和文件、正式标签/pending、操作次数、外发范围和真实结果；另外记录总耗时、模型请求数、token与可取得的费用。不要把固定唯一工具调用序列作为正确答案，但必要审批和范围校验不可缺失。

## 6. 性能和资源基线

沿用 [现行性能目标](../../docs/PERFORMANCE.md) 与 [PRD](../../docs/PRD.md) 的搜索/浏览要求。新增记录：Pi冷启动/首事件、插件首屏和切换、idle/运行内存、IPC带宽与队列长度、并发处理时搜索尾延迟、临时磁盘峰值、退出耗时。

P01/P02后再冻结具体新增阈值。不能在没有测量时承诺sidecar包体、CPU上限或多WebView硬内存隔离。所有大结果分页/分块；图片用产物句柄；模型上下文禁止全库灌入。

**预算放行责任与超限处理**：A0-02测Pi/Node/依赖解包总量、同目标同构建配置的安装包增量（MiB及百分比）、冷启动与退出；A0-03补空闲/流式请求资源。A0关口由负责人指定的架构/发布复核者依据测量批准数值预算，并在承接后的 `docs/PERFORMANCE.md` 保持唯一记录。每项必须有平台/构建条件、基线、实测、允许上限、测量方法、复核者和复核日期；当前不填虚构数值。

预算缺失或超限时，A0不得作为生产接入已放行的证据，A3-01不得以默认接受体积继续。先定位重复依赖/未用资产或运行时方案，优化后重测；确需改变上限，先提交用户可感知的代价与替代方案，由同一责任角色重新批准并留依据。不得删除必要安全/恢复能力来压包体。A3-01和A6-03使用冻结预算回归，超限阻止该卡验收；B0对新增插件容器建立独立增量预算，B4回归。

审查报告中的npm解包数字和80–110MB估算不是茶馆安装包实测，本计划不把它们转成事实基线。具体Node制品、压缩、重复资产和平台都会影响结果。

## 7. 跨平台和迁移

- Windows 10/11 x64、Apple Silicon macOS、Ubuntu 24.04 x64 分别验证受支持功能；等级依 [PLATFORM](../../docs/PLATFORM.md)。
- 最小960×640窗口、1366/1920宽度、不同DPI、明暗主题、键盘、中文输入、焦点与弹窗遮挡。
- 旧库→2.0、新库、重复启动、半迁移；FTS和标签/分面、既有搜索计划、回收站和凭据兼容。
- DB备份、插件工程、Pi会话和产物一致性；恢复后库世代与权限失效；不自动复活原生扩展信任。
- 安装/升级/卸载/再安装、进程清理、离线启动、没有Node或媒体引擎的干净机器。

## 8. 风险登记

| 风险 | 级别 | 控制/发布阻断 |
|---|---|---|
| 子WebView继承旧权限/资源URL跨插件 | 最高 | P02不通过禁止开放普通插件 |
| 模型/插件重复提交造成数据重复或重复计费 | 最高 | P03a/P03b和未知结果策略，按实际版本入口执行 |
| 原生扩展被误称为受限沙箱 | 最高 | 安装信任分级；未实现OS隔离不得作此承诺 |
| Pi辅助请求绕过凭据/预算政策 | 高 | P01覆盖所有模型请求路径 |
| Pi/MCP版本演进不一致 | 高 | 锁版本、双协议测试、fallback、升级契约测试 |
| 固定依赖版本遗漏安全修复 | 高 | 依08跟踪适用公告、评估受影响路径，升级验证或禁用，不把锁版本等同于停止维护 |
| Tauri unstable容器API与安全更新冲突 | 高 | 2.5容器实现集中到可替换Module，升级重跑P02；隔离失败禁止插件运行 |
| RAW结果误触发同源标签扩散 | 高 | 显式来源关系和kinship兼容测试 |
| 插件更新损坏工程/扩大权限 | 高 | 分步更新、迁移备份、权限差异批准 |
| 恢复备份后旧授权引用新素材 | 最高 | libraryEpoch与全入口维护闸 |
| 旧绝对路径/失联总仓被当作可清理素材 | 最高 | 保护先于清理、托管证据、待处理隔离和离线验收 |
| 迁仓半切换或去重回仓丢失整理信息 | 最高 | 维护门、稳定资产身份、核验/收据及各阶段崩溃测试 |
| 个人流程把旧批准或危险操作隐藏在模板中 | 最高 | 参数实例化、不可变版本、新计划、独立清空和宿主能力校验 |
| WebView/原生引擎资源耗尽 | 高 | 配额/限流/进程寿命；不夸大硬隔离 |
| SDK面太大，后续难维护 | 中 | 两个必需真实样例先验证，再冻结公开版本；专业RAW另设可选关口，见08 |

## 9. 发布标准与待决项

现有 typecheck/lint/unit/tooling、Rust fmt/clippy/test、build/smoke 门禁全部保留。新增接口/安全/迁移/故障注入测试和目标平台真实用户旅程；P0数据损坏/越权与P1核心流程失败不得带入正式支持范围。

共同必须交付：对应版本的支持矩阵、用户可见限制、版本锁及来源摘要、升级/恢复说明、实际测试证据。2.0 交付 Agent/Skills/MCP 使用说明；2.5 再交付插件 SDK 文档与样例、工程迁移说明。未执行项目明确列出，不用旧提交的通过结果替代新版本验收。

仍需原型决定：Pi模型传输的具体Adapter；单仓身份/相对定位与旧绝对路径迁移的字段布局；迁仓源端清理及冲突恢复的具体状态；个人流程内部参数格式和受控 Pi 加载；最小窗口下导航溢出/工作台几何；插件内嵌容器在锁定Tauri版本的可行实现；产物登记与现有importer抽取范围；每个平台原生引擎分发方式；真实资源阈值。它们是有明确通过条件的工程选择，不能借此静默改变 02 的产品决定。
