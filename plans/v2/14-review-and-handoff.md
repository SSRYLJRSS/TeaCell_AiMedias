# 任务验收、复核与交接

性质：执行方法。实际状态只记 [项目计划](../../docs/PROJECT_PLAN.md)，本文件不记录谁已完成什么。任务门禁沿用 [AGENTS](../../AGENTS.md)、[开发规范](../../docs/DEVELOPMENT.md) 与 [测试策略](../../docs/TEST_STRATEGY.md)；本页只提供可操作的验收流程和报告模板。

## 1. 一张卡通过的条件

### 状态、依赖与授权

每张卡分别记录以下证据，不用一个“已完成”合并不同层次：

| 层次 | 判据 |
|---|---|
| 实现 | 卡内模块、类型和必要测试存在，明确尚未接入的调用者 |
| 接通 | 卡内指定生产入口实际经过权限、批准、队列、worker 与结果回传；后续卡负责的 UI 接入单独标明 |
| 验证 | 正常、负向、故障测试观察到真实文件、DB、收据和状态，并通过相关门禁 |
| 独立复核 | 非本次实现者核查最终差异与失败证据，阻断问题已关闭；需设计复核的卡另有设计结论 |
| 验收 | 卡内目标、前述证据及必要真机项齐全，结论记入唯一项目计划 |

依赖只由验收解锁。发现前置未验收但下游已有改动时，保留全部已有工作，先补前置缺口和复核，再验证受影响下游；不得回滚用户工作，也不得继续扩大依赖该缺口的功能。可推进已授权且无此依赖的工作。

用户的连续开发授权持续有效，卡内修复、测试、文档同步和满足前置后的推进无需反复询问；用户之后明确扩大开发范围时，按新授权继续逐卡执行，不沿用已被替代的旧范围限制。授权只覆盖相应代码工作，不自动提供真实凭据/素材测试授权，也不扩大权限、真实外发、提交、推送或发布范围。环境缺项只阻断任务索引中直接依赖该证据的卡及其下游；可独立推进的卡继续。工具中断、审查任务失联和环境故障均保留为未完成证据，不自动成为豁免；按第5节交接并恢复核查。临时基础设施豁免仅按仓库制度记录期限、适用范围和恢复条件，不替代产品故障验证或独立复核。

### 验收证据

1. 卡内目标和行为场景全部有证据，准许范围内的代码链路实际接通。
2. 正常、负向及故障场景中，真实 DB/文件/事件结果符合契约；没有用模型文字或 mock 成功冒充真实副作用成功。
3. 定向验证与仓库要求的相关完整门禁有命令、退出码、执行数；环境阻塞准确列出，不转写成通过。
4. 权威文档已按本卡实际变化更新；拟议和已实现标记正确。
5. 差异经复核，无越界功能/权限/旧入口旁路；需设计复核的任务有结论。
6. 未提交/未发布与实际一致；只在用户明确要求时进行这些外部动作。

## 2. 验证执行

先运行本卡指定文件/模块的定向测试。前端可使用 `npm run test:unit -- <真实测试文件路径>`；Rust 在 `src-tauri` 下使用 `cargo test --all-features <已存在的测试名过滤器>`。执行 AI 先确认文件/测试名存在，再使用过滤器，检查确有测试执行。拟建测试名不是当前命令的可执行证据。

普通代码改动的完整门禁以仓库原文为准。编制时核实的命令如下；执行时先检查脚本/工具链是否发生变化，变化不是跳过门禁的理由：

```powershell
# 仓库根目录；逐条执行并记录结果
npm run typecheck
npm run lint
npm run test:unit
npm run test:tooling

# Windows 原生依赖前置；其他平台按 PLATFORM 与实际 target 准备
npm run prepare-heif-libraries -- --target x86_64-pc-windows-msvc
$env:HEIF_BINARIES_DIR = (Resolve-Path "src-tauri/native/heif/x86_64-pc-windows-msvc").Path

# 在 src-tauri 目录执行
Push-Location ./src-tauri
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
Pop-Location

# 回到根目录，交付门禁
npm run build
pwsh ./scripts/smoke.ps1
```

以上整段从仓库根开始；每条检查完成后立刻记录退出码，不能只用最后一条命令的成功覆盖前面的失败。被中断后先确认实际目录，再恢复，不重复套用 Push-Location。涉及新 sidecar/打包、MCP、路径/迁仓的任务还需其专项验证和目标平台证据。只改文档检查链接、路径、引用与内容一致性，不为此宣称运行了应用测试。

门禁绑定交付时的最终工作区：记录 HEAD、未提交/未跟踪差异范围与验证时间。验证后发生代码、契约或测试改动时，重跑受影响定向验证及相关完整门禁；改动前结果只能作历史参考。并行工作集成后统一验证，不能拼接各分支或各执行者的绿色结果宣称最终工作区通过。

独立复核也绑定明示的比较起点与最终差异：记录基线提交、审查范围、审查时工作区和复核者。复核后任何改变实现、契约、迁移或测试的修改，都要由原复核者或新的独立复核者重新检查受影响差异；此前“通过”只保留为历史结论。复核发现阻断时，立即撤回该卡的验收状态、记录阻断及修复证据，完成针对性和完整门禁后再复核；不能把初次复核或改动前的绿色结果沿用到新工作树。

恢复类任务必须经生产入口或与其共用的受理/队列/派发/worker 调用链验证，观察真实文件、DB、逐项收据和 operation 状态，至少覆盖：响应丢失后同键重试、并发重复提交与执行互斥、排队及执行中取消、重启对账与继续、文件发布后 DB 未登记、DB 登记后收据未写入、源文件在复检与读取之间变化。文件效果在发布/登记前须验证操作后的源和目标身份及契约要求的元数据；故障注入要覆盖只改 mtime、不改字节/大小的窗口，不能只用内容 hash 代替完整快照。断点须可重复注入；已成功项不重复副作用，无法确定的结果明确未知。原型、纯状态机或直接调用 worker 的成功测试不能替代这些生产接线证据。

测试数据：使用 `tempfile`/隔离目录/独立 DB fixture，包含中文/空格/同名文件、同哈希不同记录、链接/跨卷条件、损坏/不支持媒体、离线根、可控时钟/取消/故障注入。真实 API 必须由负责人提供专用测试配置和预算，默认 mock 不访问真实凭据或用户素材。

会话草稿验收须在扫描、准备、重新准备、提交和持久化的等待窗口切换会话，检查原会话记录、新会话记录和当前 UI 三处结果；再让旧投影晚于新投影返回。只测试顺序切换或按钮禁用不能证明异步归属正确。长文件读取须在首个有界块之后撤权、取消或变更库世代，检查下一块停止、真实副作用及最终操作状态；授权边界仍以[授权契约 §5](../../docs/contracts/authorization-v1.md#5-路径和打开边界)为准。打包/临时桌面验收还须按[开发规范](../../docs/DEVELOPMENT.md#2-日常命令)核对名称与确切产物路径。

## 3. 独立复核清单

复核者先读卡及需求来源，再看差异和失败场景，不能仅复述执行 AI 的总结。

| 方面 | 要求证据 |
|---|---|
| 规格 | 本卡 ID 和需求索引逐项对应；没有额外承诺的功能 |
| 入口 | UI/Pi/MCP 能力范围正确，旧命令不会绕开批准/托管验证 |
| 数据 | 迁移追加、资产身份/关联保留，文件与 DB 半完成可恢复 |
| 安全 | 权限来自宿主；输入、外发、清空、到期清理与维护范围正确 |
| 状态 | 同一任务只有一个执行事实；排队、取消、等待、结果未知可区分 |
| UI | 真流程可操作、弱网/错误可理解；错误恢复指引遵守 [开发规范 §3.3](../../docs/DEVELOPMENT.md#33-tauri-ipc)；最小窗/DPI/键盘正确 |
| 平台 | 新能力显式受支持或降级，构建成功不冒充真机支持 |
| 测试 | 测试观察真实行为，不只断言被 mock 的函数被调用 |

数据丢失/越权/重复副作用及核心流程失败阻止该任务通过。环境缺失保留“未验证”，由负责人安排验证，不用 reviewer 文字把它豁免成成功。允许的临时基础设施豁免遵循仓库制度，必须有期限和恢复条件。

交接报告放在当前任务说明/PR/项目计划引用的证据位置；不新增日期化长期报告。代码中不遗留生产假实现来“占位完成”。如果设计复核改变接口，先更新唯一契约及依赖卡，再恢复下游执行。

## 6. 依赖升级责任与放行

Pi基线的唯一落点是 [03 §1.1](03-agent-and-mcp.md#11-核实版本)，资源预算的定义/归属见 [09 §6](09-validation-and-risk.md#6-性能和资源基线)，Tauri插件容器变更策略见 [05 §3.2](05-plugin-platform.md#32-降级与不采用的捷径)。执行任务时发现新版并不授权自动安装或改锁文件。

| 责任 | 谁承担 | 何时必须交付 |
|---|---|---|
| 首轮基线清单 | A0-02执行者；模型传输由A0-03补充 | A0关口前登记Pi/Node/同组包、锁文件摘要、官方来源、许可、运行模式和安全修复适用性 |
| 后续升级影响分析 | 负责人另行派出的Agent Host维护任务执行者 | 改依赖前提交新旧版本、受影响契约/路径、适用修复、验证与回退方案 |
| 安全/兼容复核 | 负责人指定、能判断权限与数据风险的复核者 | 对下列证据作出放行或阻塞结论；不能用执行者一句“已兼容”代替 |
| 发布前最终核实 | A6-03/A6-04；插件阶段为B0/B4责任任务 | 核对当前锁定组合、适用安全公告、预算和真实打包证据 |

同一人可以承担多项维护工作，但完成报告须明确执行与复核角色；责任人未知则由负责人先分配，升级任务不自行继续。实际责任与证据记在该任务及 `docs/PROJECT_PLAN.md`，不另建长期升级进度账。

升级任务逐项检查：

1. **范围**：核对官方release/tag/源码差异，区分SDK、CLI和standalone；评估修复是否影响茶馆使用路径。无需沿用报告中的时间估算；根据实际差异定范围。
2. **制品**：精确固定直接版本、传递依赖锁文件、Node和附带资产摘要；检查支持平台、许可证/源码材料。运行时不执行Pi自更新。
3. **工具与环境**：重跑P01的全部模型路径、环境哨兵/代理矩阵，核对tools/loader/reload/信任配置和密钥边界；新增工具默认不进入茶馆允许集合。
4. **事件与会话**：核对 `agent_settled` 等事件、取消/完成区分、会话格式、压缩/总结/恢复；现有transcript使用副本测试，不覆盖唯一用户记录。v1.1.0的 `aborted` 与工具修饰语法是已知例子，不能把它们当升级差异的完整清单。
5. **业务与生命周期**：复跑受影响E案例、P03恢复及P06退出/双开/残留进程测试。Node能启动不等于工具效果幂等；停推理不等于取消Rust操作。
6. **预算与文档**：依冻结预算测同配置制品，超限按09处理；更新所有受影响事实、tag/行号引用、能力矩阵和依赖任务。旧引用可保留为明确历史对照，不能支持新版行为声明。
7. **回退**：说明代码制品是否可退、数据/会话格式是否可逆及备份位置；格式已变而旧版本不能读时，禁止仅替换二进制就称回滚成功。失败保留可恢复数据并阻断升级交付。

存在适用的阻断性安全问题时，选择修复升级或禁用受影响能力；不能以“方案锁定旧版”为理由继续发布。涉及2.5容器升级，额外重跑P02及05的安全降级路径。
