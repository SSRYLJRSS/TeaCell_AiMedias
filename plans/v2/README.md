## 推荐结论

现有项目适合渐进改造，保留 Tauri、React、Rust、SQLite、SearchPlanV3 和 imaging。用户已明确分成两个大阶段：**2.0 完成垂直素材 Agent，2.5 再开发插件系统。** 2.0 完整接入 Pi SDK，由 Rust 统一执行素材操作，并按此前需求在核心链路完成后提供 stdio MCP；插件只预留必要的内部业务 Interface 和接入设计，不开发安装器、容器、工作区或公开 SDK。

2.0 先验证 Pi 模型治理、sidecar 生命周期和导入/打标任务恢复；2.5 再验证插件容器隔离与媒体产物流程。HTML/JS + 宿主 SDK 仍是插件推荐方向，实际格式在 2.5 启动时重新核实。原生软件接入独立分级，不把同账户 Node 子进程宣称为恶意代码沙箱。

**准备派工先读 [11 执行指导书](11-execution-guide.md)**：包含单卡与连续授权边界、最小阅读包、完成与停止条件。再从 [任务索引](execution/README.md) 选择一张前置已验收的卡；任务卡数量只用于定位，不代表完成比例。首次执行从A0-01核实基线，接续执行先查PROJECT_PLAN中的真实证据。规划完成不等于功能完成或验收通过。

**看整体开发顺序读 [08 两个大阶段的开发步骤](08-migration-and-delivery.md)**：包含2.0的A0–A6和2.5的B0–B4。08说明版本范围与大阶段，产品范围以PRD为准；任务卡负责可执行拆分，实际交付进度仍只记在权威 PROJECT_PLAN。

**核对本轮产品决定请读 [02 的 UI 与分期范围](02-target-architecture.md#ui-与分期范围)**：该节跳转到权威PRD，涵盖默认五入口与底栏自定义、双工作台、应用内悬浮助手、会话/任务、单总仓、独立清空、旧数据处置、迁仓向导和个人常用流程。用户行为由PRD第8节拥有，技术授权/恢复由 06 拥有，执行步骤由 08 拥有，验收映射由 09 拥有；不另建一份访谈流水或第二套产品需求。
