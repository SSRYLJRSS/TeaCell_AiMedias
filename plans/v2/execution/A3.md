本文件为静态任务卡。先读 [执行总入口](../11-execution-guide.md) 与 [任务索引](README.md)。每次只读并执行分配的一个 ID；代码范围均相对于仓库根。新增名称在 [12](../12-implementation-contracts.md) 明确为拟建。所有卡同批包含必要定向测试/权威文档，门禁和交接执行 [14](../14-review-and-handoff.md)，未列出不代表可以省略。

- 允许范围：拟建 packages/agent-host/、Rust agent_runtime、构建资产声明及相应测试；使用已锁版本。

1. 把通过原型的 Host 引入正式构建，限定资源/会话目录和环境，使用应用拥有的进程与握手。
2. 实现请求/事件framing、精确版本握手、消息限制、实例/run ID、取消和03 §2.1的用户触发恢复；stdout只承载协议。验证退出期间不重启、同目录双开不产生第二写者。
3. 在开发/打包路径测试无全局 Node、Host 异常和旧实例迟到事件；只声明实际支持平台。
4. 使用A0已批准的版本组合与资源预算回归实际打包制品；差异/超限按09 §6处理，不能临时换最新版或放宽预算。

**验收与交付：** 无用户全局 Pi 配置也可工作；Rust 对 Host 帧执行精确字段、类型、引用和错误类别校验，命令拒绝能以固定分类诊断且不泄露原始文本；ACK 与请求的 command、conversationId/runId 一致，否则按结果未知处理；旧事件不能污染新 run；数据根规范化后必须仍是应用数据目录的直接子目录，且数据根/会话目录拒绝链接并固定目录身份后再写入。SDK 的会话发现必须使用固定目录快照；只对名称以目标 `conversationId` 结尾的 `.jsonl` 候选，在读取头部前由 Rust no-follow 打开并固定文件身份，且拒绝重解析点和多重硬链接；其他会话文件不能用目标 ID 请求 pin。新增会话也须先独占创建头部再固定，SDK 只能接收已 pin 的直接普通文件；关闭会话按 conversationId 释放其文件句柄。退出回收 owned 进程，无第二业务 DB。

**停下条件：** 原型与生产打包路径不同且未经验证，或真实凭据泄入环境时阻断。

## A3-10

**Agent 会话权限档位**

- 前置：A3-02、A3-04、A3-06。
- 需求索引：R61，另影响 R33、R48、R50，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：12 §6.2、§3；06 §2、§3；[内部协议 §2、§4](../../../docs/contracts/agent-host-protocol-v1.md)；`src-tauri/src/services/agent_runtime/capabilities.rs`、`permission.rs`（新建）、`src/components/assistant/Composer.tsx`。

**背景。** 当前 16 个模型工具按 `AccessKind` 天然分三层：`Query`（`assets.search`、`operations.get`、`workflows.load`）、`Prepare`（六项 `*.prepare`）、`Submit`（六项 `*.submit`），另有 `operations.cancel` 属 `Cancel`。用户需要在不改变审批链的前提下，控制助手在一次对话里能用哪一层。

1. 定义 `AgentPermission::{Read, Standard, Full}`，默认 `Standard`。`Read` 只放行 `Query` 与 `Cancel`（4 个工具）；`Standard` 在此之上排除 `assets.move.*` 与 `assets.trash.*` 两族（12 个工具）；`Full` 是全部 16 项。三档单调递增，且每个被暴露的 `*.prepare` 必须同时暴露其 `*.submit`，不得出现「能准备不能提交」的死档。
2. 两道门，缺一不可：`conversation.open` 按档位裁剪工具表（体验门）；`capabilities::execute` 在 `dispatch` 前按档位再判一次（安全门，权威）。安全门判据从 `descriptor.access` 推导外加一个显式声明的两族排除集，描述表缺项时**不放行**，手法对齐 `ensure_maintenance_allows`。`conversation.open` 帧里的 `permission` 字段由 Rust 依据用户选择写入，**不接受 Host 或前端在能力调用帧中回传的档位字段**。
3. 档位为会话级，不写入 `conversations` 表持久化，关闭会话即删表项；新会话回到默认 `Standard`。换档一律「关闭 Host 会话 → 用新档位重开」；在途 run 期间换档入口禁用，不中断 run，不清空草稿。档位表缺项时安全门拒绝一切能力调用，不回落更宽档。
4. 与审批链的关系写死：`plans.approve`、`operations.resume`、`trash.empty.*`、打标开始在任何档位下都保持 GUI 专属，`Full` 亦不例外。`Full` 只让模型多看见移动与删除这两族工具，它们仍走 prepare → 用户批准 → submit，不得自动批准。

**验收与交付：** 三档工具集是 `SUPPORTED_PI_CAPABILITIES` 的稳定子集且严格单调递增（逐个精确断言 4 / 12 / 16，遍历 `CAPABILITY_DESCRIPTORS`）；`Read` 与 `Standard` 档下越档能力被 Rust 拒绝且错误码可解释；档位表缺项时拒绝全部能力调用；Host 侧被篡改送来档位外能力时安全门仍拒绝；GUI-only 能力永不进入任何档；`npm run test:agent-host` 覆盖三档的 `open → ready → capability.request` 全链路。

**停下条件：** 档位只在 prompt 或前端禁用按钮生效、后端无拒绝证据时不通过；档位改变任一 `approval` 语义时不通过；出现「prepare 可见而 submit 不可见」的死档时不通过。

## A3-11

**网关外发安全证据与对话准入**

- 前置：A3-02。
- 需求索引：R33、R50、R61，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：12 §6.1；06 §8；`src-tauri/src/services/agent_runtime/gateway.rs`。

**背景。** [12 §6.1](../12-implementation-contracts.md#61-a3-02-agent-模型网关接线) 原先记录：对外部 DNS、系统代理、TUN、loopback/私网与 DNS rebinding 的安全结论尚未取得生产证据，故生产网关 capability 保持关闭。**2026-11-01 产品负责人裁决改变了这件事**：外发不再有用户可见的「允许联网」开关，配置好 API 即可直接对话；准入由绑定+启用+密钥推导，权限分级只控制文件操作档位。本卡因此不再是「先拿证据才准开」的前置，而是**开了之后必须补齐的证据与预算政策**。

1. 把可验证的拒绝项做成不静默跳过的负向测试并留存证据：重定向不跟随（`redirect::Policy::none()`）、连接地址含 userinfo 被拒、代理地址拒绝账号密码/路径/query/非 http(s)（`validate_agent_proxy_url`）、`DisabledGatewayTransport` 失败关闭、未绑定/已停用/缺密钥三种 preflight 码各一例。**loopback 必须被显式允许**（本机 Ollama 是受支持部署），把「127.0.0.1 一律拒绝」当验收标准即错误。
2. 把当前硬上限固化为用户可见默认值与确认政策并落 [06 §8](../06-permissions-and-data-safety.md#8-网络凭据与预算)：每 run 8 次 HTTP attempt、单 run 180 秒、每 attempt 请求体 2 MiB/响应体 1 MiB、每 attempt max output 2,048 tokens；说明费用不可预估时如何提示用户。
3. 真实 provider 证据：补齐 `--ignored real_provider` 三项（错误/取消/限流）在隔离新凭据下的实测记录，并写清「哪些结论来自 fixture、哪些来自真实链路」；未取得即如实标注未验证，不得用 fixture 结果代替。
4. `modelNetwork: false` 与 `docs/contracts/agent-host-protocol-v1.md` 的 Host 无直连网络约束原样保留，不因本卡放宽。

**验收与交付：** 第 1 项每个场景有独立负向测试；第 2 项数值在 06 §8 有唯一出处且代码常量与之逐项一致；文档中不再残留「生产 capability 必须保持关闭」「请打开联网开关」这类旧表述（12 §6.1 已改写，需复核一致）；未绑定、已停用、缺密钥三种情形分别给出具体缺项提示。

**停下条件：** 任一项拒绝场景仅靠黑名单声明而无实测证据即不通过；把 loopback 一刀切禁止即不通过；用 fixture 结果冒充真实链路证据即不通过。
