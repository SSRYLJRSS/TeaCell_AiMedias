# A5：外部 MCP 接入与多入口一致性

本文件为静态任务卡。先读 [执行总入口](../11-execution-guide.md) 与 [任务索引](README.md)。每次只读并执行分配的一个 ID；代码范围均相对于仓库根。新增名称在 [12](../12-implementation-contracts.md) 明确为拟建。所有卡同批包含必要定向测试/权威文档，门禁和交接执行 [14](../14-review-and-handoff.md)，未列出不代表可以省略。

## A5-01

**受控 stdio MCP 入口与宿主连接**

- 前置：A4-08。
- 需求索引：R04、R03、R48，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：03 的外部 MCP 和当前版本依据；06 的调用者边界；12；A0-02 生命周期协议；src-tauri/src/services/platform.rs、src-tauri/src/utils/process.rs。
- 允许范围：拟建 packages/mcp-bridge/ 与 Rust 本机 IPC 适配、配对管理入口、构建配置和测试；不启动公网服务。

1. 实施时复核并固定 MCP SDK/协议版本，在现有受控能力之上建立 stdio 适配；桥接进程没有独立数据库连接或文件写执行权。
2. 连接真实茶馆宿主并验证本机身份/配对；分离协议 stdout 与日志 stderr，输出去敏。宿主未运行时按定稿生命周期返回清楚的启动/连接提示，不静默另起一个写库宿主。
3. 配对信息由可信设置界面管理，可撤销；每次调用带可验证 caller 身份与允许范围，客户端自报名称/参数不能充当权限证据。

**验收与交付：** 至少一个独立 MCP 客户端能初始化和列出允许工具；假身份、撤销配对、错误 IPC 端点、宿主退出得到确定错误，日志不破坏协议也不含密钥。

**停下条件：** 协议版本/配对安全/进程启动语义尚未冻结，或需要绕过 Rust 单一写入口时停止。

## A5-02

**对外发布查询与准备计划工具，由茶馆确认写入**

- 前置：A5-01。
- 需求索引：R04、R26、R48、R58，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：03 工具表；06 审批边界；docs/contracts/search-plan-v3.md、docs/contracts/facets-v2.md；A1 的工具 schema 和选择集合。
- 允许范围：MCP 工具适配、茶馆外部请求审批展示、任务结果查询与测试；不增加独立业务实现。

1. 读取工具返回受控查询结果/资源引用，限制字段和数量，不能通过可读资源暴露任意本地路径文件或凭据。写操作只准备可审查的计划，显示外部调用者、作用范围和风险。
2. 在茶馆可信完整界面完成批准/拒绝；外部模型不能传 approved=true、伪造按钮点击或签发 Approval。清空回收站仍使用固定 N 的专属交互。
3. 任务响应提供稳定任务 ID 和查询接口；长任务遵循普通状态轮询/通知兼容路径，不要求所有客户端实现实验性 Tasks。客户端断开不会自行重做写操作。

**验收与交付：** 从外部客户端查询、准备导入、茶馆确认、查看收据全链路通过；拒绝不产生写入；重复请求不重复导入；外部‘已获用户许可’文本无效。

**设计结论（2026-10-26 用户裁决 A，收窄本条「准备导入」）：** 「准备导入」一项经设计复核**移出 2.0 交付范围**，其余验收不删不减。理由与禁止绕过项见 [MCP 桥接契约 §4.1.1](../../../docs/contracts/mcp-bridge-v1.md#411-为什么-20-不发布-imports设计结论不是待办)：目录授权只能由 GUI 通过原生选择器创建，句柄绑定 principal+instance+session，而 MCP 调用方的 `session_id` 恒为 `None`，为 GUI 会话签发的句柄在外部必然解析失败；唯一能打通的口子是让用户手工把 `directoryRef` 抄进客户端配置，等于用「用户别抄错」替换会话隔离。因此「准备导入」按「外部查询 → 准备计划 → 茶馆确认 → 查看收据」执行，导入/导出继续由本机可信界面驱动。本条不改 `docs/contracts/mcp-bridge-v1.md` §4.1 的 5 项可发布集合。

**停下条件：** 客户端与本地会话混淆权限或工具暴露了原始 SQL/任意文件操作时停止。

## A5-03

**MCP 与 GUI/内置助手并用的互操作验证**

- 前置：A5-02。
- 需求索引：R04、R51、R53，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：09 的多入口矩阵；A5-01/02 schema；A1 排队/取消/恢复；docs/PLATFORM.md。
- 允许范围：MCP 集成测试、平台启动适配、错误提示和必要修复；不拓展新工具。

1. 用至少两个实际选择并记录版本的客户端验证初始化、查询、写计划、拒绝和状态获取；客户端能力不同只影响体验，不改变业务授权。
2. 交错发起 GUI、内置 Agent、MCP 写任务，验证统一排队及选择集合快照；迁仓/恢复期间外部写入被维护状态阻断，撤销配对立即影响新请求和未执行敏感步骤。
3. 检查断线重连、请求重试、任务已完成后客户端恢复、宿主崩溃与干净退出；对平台缺失能力返回一致的禁用说明。

**验收与交付：** 提交客户端/平台/版本/场景证据；已完成操作不被重放，无第二个写库宿主；未运行平台明确未验证并按发布门禁处理。

**停下条件：** 无法在真实客户端复现、只通过 mock 却准备声明兼容，或权限撤销时的在途策略未落实时停止。
