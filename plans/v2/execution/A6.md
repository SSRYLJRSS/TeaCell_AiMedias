# A6：完整验收与交付复核

本文件为静态任务卡。先读 [执行总入口](../11-execution-guide.md) 与 [任务索引](README.md)。每次只读并执行分配的一个 ID；代码范围均相对于仓库根。新增名称在 [12](../12-implementation-contracts.md) 明确为拟建。所有卡同批包含必要定向测试/权威文档，门禁和交接执行 [14](../14-review-and-handoff.md)，未列出不代表可以省略。

## A6-01

**逐条覆盖产品验收与完整桌面旅程**

- 前置：A5-03。
- 需求索引：R06、R59、R60，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：普通复核。
- 必读：13 的需求任务映射；09；docs/QA_PLAYBOOK.md、docs/TEST_STRATEGY.md；A3/A4 已交付页面。
- 允许范围：正式测试/真机验收条目及发现问题的最小修复；更新权威需求验收引用，禁止改低标准。

1. 逐条核对 R01–R60 的适用版本，区分2.0必需、2.5储备和工程约束。每项关联真实用例/测试证据，不能只写‘相关组件已存在’。
2. 走新用户引导→配置→拖图→预检→确认导入→打标建议→审核→素材库结果→离开页面继续聊；另走纯手动无AI、独立入库交接、旧会话恢复、个人流程等路线。
3. 验证最小受支持窗口、手动改宽、收起历史、长中文、多任务进度轮播/悬停、键盘焦点与窗口内悬浮窗；误点、重复点击和异常场景纳入验收。

**验收与交付：** 无必需需求未映射；桌面真机与自动测试分别记录，未执行项不能算通过；普通功能不被新布局遮蔽或移除。

**停下条件：** 发现需求相互冲突或新增用户行为需要决策时停止对应分支，不用自己的偏好替代已确认决定。

## A6-02

**数据库升级、备份恢复和中断注入验收**

- 前置：A6-01。
- 需求索引：R51、R52、R55、R57，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：docs/OPERATIONS.md、docs/DEVELOPMENT.md；06/12；src-tauri/tests/db_integration.rs、src-tauri/tests/services_integration.rs；src-tauri/src/services/backup_restore.rs。
- 允许范围：迁移/服务/恢复测试、备份恢复业务必要修复；不修改已发布迁移。

1. 用受支持旧版本数据库副本和脱敏媒体夹具覆盖空库、普通库、已有AI任务、库外历史记录、回收站和个人流程升级；重复启动/重复迁移应幂等。
2. 在文件效果前后、收据写入前后、事务提交前后、跨进程响应丢失等断点测试恢复；核对文件实际存在、数据库、标签关系与用户可见结果，不仅核对函数返回值。
3. 备份恢复验证素材引用/会话关联、配置/凭据的既定边界，恢复后重新核验总仓身份和授权代次；不得从旧备份复活可直接写入的批准凭证。

**验收与交付：** 具备正常升级、失败回退/恢复、中断继续、撤权和缺文件案例的可复现证据；原资料与元数据不静默丢失；旧数据问题有明确隔离和处理入口。

**停下条件：** 备份不完整仍被标为可恢复、恢复激活旧审批或测试依赖真实用户资料时停止。

## A6-03

**打包、平台、性能和模型可靠性验收**

- 前置：A6-02。
- 需求索引：R50、R53、R54、R57、R59，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：docs/PLATFORM.md、docs/PERFORMANCE.md、docs/TEST_STRATEGY.md；09；Pi锁定版本与 A0/A3 模型网关结论。
- 允许范围：现有构建/CI/平台能力/性能测试和必要最小修复；涉及运行时依赖需明确平台支持。

1. 在目标平台干净环境验证安装、首次启动、内置运行时、子进程路径含空格/中文、退出无残留、升级后恢复；开发机能启动不等于安装包通过。
2. 复用性能基线并增加助手空闲资源、会话切换、任务队列、大批入库和并发读；报告测试数据量/硬件/阈值来源，对比旧功能防退化，不伪造通用耗时指标。
3. 以离线假服务验证重试/取消/限流/隐私，真实模型调用仅在获准测试预算和脱敏数据下执行。记录服务/模型版本、代表性指令成功/拒绝/错误；既有 RAW/HEIC/视频链路继续回归，不声称已实现专业显影。
4. 对照03/14的精确依赖基线及适用安全修复，核实整个case集、环境/代理和生命周期矩阵；依09的冻结数值预算判定包体/启动/资源，不能只提交测量数字而不判断是否超限。

**验收与交付：** 平台矩阵有真实编译/测试/打包证据或按现行规范处理的未通过项；至少目标主平台真机全链路；网关覆盖全部模型请求；新增资源占用可解释。

**停下条件：** 只测开发模式、模型未实际验证却宣称全兼容、受支持平台失败或准备靠新增无限重试压住失败时停止。

## A6-04

**2.0 交付复核、操作说明与阶段关闭**

- 前置：A6-03。
- 需求索引：R01、R53、R59、R60，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：14 的完整门禁；docs/PROJECT_PLAN.md、docs/PRD.md、docs/ARCHITECTURE.md、docs/OPERATIONS.md；13 的适用范围。
- 允许范围：权威文档、验收记录和发现缺陷的独立最小修复；不自动提交/打标签/推送/发布。

1. 按仓库要求完成完整质量门禁和冒烟，收集独立复核结果；核查没有被跳过的必要测试、测试断言削弱、假成功提示和无依据状态。
2. 把已交付行为与未完项真实更新到权威文档，清理方案与实现之间失效的链接/术语引用；本目录保留设计依据，不继续承载第二份当前进度。
3. 交付面向用户的配置、授权、恢复、迁仓、个人流程和外部 MCP 使用说明；列明平台/模型实测范围、已知限制和可恢复路径。2.5 必须重新经过 B0，不因已有百宝箱入口就宣称插件已支持。

**验收与交付：** 2.0必需条目均有通过证据，高风险复核已关闭；明确说明是否仍有发布阻塞；源码开发完成与实际发布是两个状态，发布等待另行明确授权。

**停下条件：** 任何必要门禁未通过、恢复/永久清理缺少可信证据或产品范围被偷偷删减时，不得宣告2.0完成。
