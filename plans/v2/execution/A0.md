# A0：基线与关键原型

本文件为静态任务卡。先读 [执行总入口](../11-execution-guide.md) 与 [任务索引](README.md)。每次只读并执行分配的一个 ID；代码范围均相对于仓库根。新增名称在 [12](../12-implementation-contracts.md) 明确为拟建。所有卡同批包含必要定向测试/权威文档，门禁和交接执行 [14](../14-review-and-handoff.md)，未列出不代表可以省略。

## A0-01

**核实基线并承接已批准需求**

- 前置：负责人明确派工；首次执行建立基线，接续执行先核实PROJECT_PLAN及工作区已有证据，不假设从零开始。
- 需求索引：R01、R59、R60，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：AGENTS.md、docs/README.md、docs/PROJECT_PLAN.md；02 的产品决定及 13 索引。
- 允许范围：本卡只允许权威文档中的 2.0 待实现条目与任务证据；读取代码和配置，不创建生产功能。

1. 记录 HEAD、工作区原有改动、工具链/脚本和现有门禁状态；已存在失败要有复现证据，不清理用户改动。
2. 将已批准行为按职责承接到 PRD/UI/ARCHITECTURE/PLATFORM/PROJECT_PLAN，明确待实现及旧行为差异；按仓库规则消除长期双写，保留本方案的任务/验收引用。
3. 列出本轮之后出现的新决策冲突；当前已确认决定不重复征询。安排后续原型只能使用独立临时素材与 DB。

**验收与交付：** 交付基线报告、文档差异和需求索引定位；未实现状态准确，现有失败/环境限制可重现；所有需求均有权威落点或明确承接位置。

**停下条件：** 若新代码/新决策与规划矛盾，先提交具体冲突；不能以本次旧规划覆盖较新的授权。

## A0-02

**验证完整 Pi sidecar 的生命周期**

- 前置：A0-01。
- 需求索引：R02、R54，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：03 的版本/宿主协议；src-tauri/src/utils/process.rs、src-tauri/tauri.conf.json、package.json。
- 允许范围：独立可丢弃 PoC 及测试目录（位置先在报告声明）；本卡不接真实素材业务。

1. 使用03 §1.1指定的精确Pi版本作为首轮基线，核实来源和许可，固定匹配Pi包、锁文件及Node制品版本/摘要；需要升级先执行14 §6，不自行选latest。
2. 用应用专用目录/受控环境启动 Host，握手版本，跑模拟流式事件；验证启动失败、异常退出、stdout 污染、超时与只回收自己创建的进程。
3. 记录实际 JS/WASM/native 资产及打包方式，验证用户无系统 Node 的路径；给出后续宿主协议选型和平台未验证项。
4. 按03 §2.1验证手动恢复、正常退出时序、主进程强杀后的残留回收、同数据目录双开与旧Host迟到事件；记录平台机制和超时，禁止按进程名误杀其他Node。
5. 按09 §6测量sidecar解包总量、安装包增量、启动/退出，提交测量与预算建议供后续A0-03汇总；此卡不等待尚未执行的A0-03。最终数值预算必须在A1-01之前完成复核。

**验收与交付：** 有启动→握手→事件→停止→退出实测，附强杀/双开/恢复失败结果；杀Host不创建第二DB owner；版本不符明确失败；哨兵环境与制品测量可复现。交付预算建议后可进入A0-03；本卡通过不代表最终资源预算已批准。无真实密钥进入进程环境/日志。

**停下条件：** 若依赖只能靠用户全局 Pi/Node 配置运行，原型未通过，不能进入生产接入。

## A0-03

**验证模型网关所有调用路径**

- 前置：A0-02。
- 需求索引：R33、R50，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：03 模型网关；src-tauri/src/services/ai_cloud.rs、src-tauri/src/services/credentials.rs、src-tauri/src/services/ai_rate_limit.rs；src-tauri/src/db/ai_connections.rs。
- 允许范围：独立模型传输 PoC、mock 服务与证据；真实服务仅用明确授权测试配置。

1. 比较已提出的受控 fetch 与私有网关候选，选一个通过测试的 Adapter，记录否决原因，不同时建两套生产路线。
2. 用可控 provider 覆盖普通回复、工具续轮、人工/自动压缩、总结、重试、截断恢复、取消；核实所有真实出站尝试经过凭据/限流/预算。
3. 验证 401/429/断网/流中断/配置切换，检查密钥不会到前端或 Node；记录协议和模型能力白名单，不把 catalog 名单当支持证据。
4. 按03 §2.2及09 §1执行系统/环境代理对照和哨兵.env测试，分开记录Node与Rust真正出站位置；缺测试环境明确未验证，不能改用户真实配置冒充隔离测试。
5. 测量空闲与流式请求的资源占用，汇总A0-02制品/启动测量，提交09 §6的最终数值预算并取得复核结论；把测试环境、流中断和取消的实际结果写入报告。

**验收与交付：** 调用覆盖表每行有观察证据；不支持的路径明确禁用；重试计数准确、取消释放占用、失败不自动换服务；环境/代理矩阵有真实结果或明确阻塞。资源预算已经数值化并获复核，且本卡需设计复核通过后，才解锁 [A3-02](A3.md#a3-02)（同时满足 [A3-01](A3.md#a3-01) 前置）。[A1-01](A1.md#a1-01) 只依赖本卡已验证的 mock Adapter 选择和非外发设计结论；真实 provider、凭据注入及代理/TUN 矩阵仍由本卡后续验证，不阻断 A1-01。

**停下条件：** 有一条辅助请求绕过治理就阻断对应 provider；不能以禁用测试或暴露密钥通关。

## A0-04

**证明文件与数据库恢复方案**

- 前置：A0-01。
- 需求索引：R49、R51、R52、R59，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：06 的计划/幂等/恢复；src-tauri/src/services/importer.rs、src-tauri/src/services/export_local.rs；src-tauri/src/db/ai.rs、src-tauri/src/db/export.rs。
- 允许范围：临时SQLite/临时文件PoC与注入测试，拟建 tests/agent-evals/ 初始case与说明及最小runner；不迁移正式schema。

1. 实现最小 prepare/approve/submit/receipt 原型，明确批准消费与 operation 创建的同一短事务。
2. 在文件复制一半、文件已发布 DB 未登记、DB 已写响应未回、子任务已创建关联回传丢失处注入退出。
3. 重启后从收据/固定 step 身份核实事实；同提交重试返回同操作；无法核实的外部请求保持结果未知。
4. 创建09 §5指定的E01–E08初始评估集，用政策替身与假模型运行，记录schema、case版本、位置和准确命令。受控故意错误必须能使断言失败，恢复后再通过；A3接生产路径继续复用同一case ID。

**验收与交付：** 每个断点有实际DB/文件比对；相同任务不重复文件/子批次；IO不在DB锁内。E01–E08及runner可执行，有失败检出证据；原型通过与尚未验证的生产路径明确区分。

**停下条件：** 恢复只能靠聊天计数或全量重新导入时不通过；先修协议再写生产任务引擎。
