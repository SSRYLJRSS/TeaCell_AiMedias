# A2：可靠导入、旧数据处置与打标链路

本文件为静态任务卡。先读 [执行总入口](../11-execution-guide.md) 与 [任务索引](README.md)。每次只读并执行分配的一个 ID；代码范围均相对于仓库根。新增名称在 [12](../12-implementation-contracts.md) 明确为拟建。所有卡同批包含必要定向测试/权威文档，门禁和交接执行 [14](../14-review-and-handoff.md)，未列出不代表可以省略。

## A2-01

**把导入扫描变成固定范围的准备计划**

- 前置：A1-06。
- 需求索引：R19、R21、R22、R26，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：普通复核。
- 必读：src-tauri/src/commands/import_cmd.rs、src-tauri/src/services/importer.rs、src/api/import.ts、src/components/import/PendingList.tsx。
- 允许范围：导入 prepare Module、预检类型、src/api/import.ts 与定向测试；复用统一 imaging，不改格式处理语义。

1. 将扫描/检查与正式入库分开，保留文件夹递归、去重、大小/类型、unsupported/limited/警告明细。
2. 绑定授权目录、文件指纹、目标分库和改名预览到计划；允许用户剔除不可处理项后重新准备。
3. 扫描取消指向准确任务/草稿；输入变化、权限撤销和目标不可用给出结构化错误。

**验收与交付：** 只拖附件不复制/落正式资产/外发；不支持项不会被确认后重新塞回清单；显示改名规则与实际后端计算一致。

**停下条件：** 如果只保存路径而不能识别计划期间文件变化，返回契约修订，不先接模型提交。

## A2-02

**执行可靠导入与恢复**

- 前置：A2-01。
- 需求索引：R20、R21、R22、R29、R30、R51，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：src-tauri/src/services/importer.rs、src-tauri/src/commands/import_cmd.rs、src-tauri/src/db/assets.rs；A1-05。
- 允许范围：导入服务/收据/任务 Adapter、领域测试；不新增平行 importer。

1. 让手动导入也走批准/受理流程，按计划处理并记录每项输入、目标、Asset ID、重复映射与失败。
2. 复用去重和 imaging，通过暂存/校验/排他发布/登记连接文件与 DB；保持锁外 IO。
3. 实现取消、重复提交、响应丢失和重启对账，已成功项不重导入，取消后成功项保留。

**验收与交付：** 按 [14 的生产恢复验证要求](../14-review-and-handoff.md#2-验证执行) 覆盖 A0-04 对应生产路径，并证明确认受理、队列派发、取消及恢复入口真正接通；重复项有真实映射；未知/部分失败不显示全成功；源文件变化拒绝或新计划。A2-05 才负责独立入库页面迁移，服务接通不得报告为页面闭环完成。

**停下条件：** 已有正式文件与 DB 不一致却只能提示重新导入时不能验收。

## A2-03

**处理历史库外记录且保留整理信息**

- 前置：A2-02。
- 需求索引：R39、R40、R52，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：12 §4、06 §7.2；src-tauri/src/db/assets.rs、src-tauri/src/services/importer.rs、src/pages/SettingsPage.tsx。
- 允许范围：旧记录处置服务/API、待处理清单 UI、追加迁移与集成测试；不自动处置真实用户历史记录。

1. 展示可验证的旧库外/未知项，区分根失联与根身份不符；提供复制回仓或解除关联的准备、确认和结果。
2. 复制回仓保留既有 ID/标签/评分/关系；同哈希碰撞用已冻结的冲突流程，不走普通 duplicate 直接结束。
3. 复制准备时把重新选择的源快照与旧资产行的大小、既有毫秒修改时间对比；不一致时保留旧记录并降为 `unknown`，不创建处置收据。处置收据另存操作系统可报告的完整修改时间精度；解除关联确认与回仓复制/复核/发布/登记均比较该精度。旧活动收据缺少精度字段时迁为 `outcome_unknown`，不继续执行。
4. 解除关联只改变管理关系，保留库外原文件；在复制、关联切换及解除中断点测试恢复，未决定项保持待处理。回仓内容先复制到 `.legacy-stage` 中由收据身份绑定的暂存文件；复制后、发布目标和登记资产前，再核验源句柄及路径的身份、大小、完整修改时间和摘要及暂存内容；即使只改变亚毫秒时间戳也不得发布，正式目标始终不得作为续写文件。若复制报错但总仓、源/资产快照、旧资产快照及持久化暂存对象身份仍可核验，保留 `copying` 供用户显式重试；证据不足才标记 `outcome_unknown`。已发布目标在恢复时若缺失、身份变化或内容无法证明，必须转为 `outcome_unknown`；资产登记前再次核验收据身份/摘要，核对导入证据中的身份/摘要与收据一致，并在数据库提交期间固定 Windows 目标句柄。正式目标通过同卷硬链接原子且不覆盖地发布；文件系统不支持时返回明确错误并保留证据。当前没有可用的安全迁仓入口，用户应保留现场，不要手动移动暂存文件或复用旧收据；迁仓后重试须由受控迁仓流程提供，支持范围见 [PLATFORM §9](../../../docs/PLATFORM.md#9-20-agent平台增量)。

**验收与交付：** 外部文件内容/时间不因解除关联而被删改；已整理信息不静默丢失；自动清理始终绕开待处理项。根离线或身份不符时逐项处置禁用；unknown/missing 只展示。哈希冲突按[实施契约 §4.1](../12-implementation-contracts.md#41-总仓与待处理记录)展示并保留为独立记录，不自动合并；解除关联保留资产行及全部整理关系并可重新打开待处理。恢复测试覆盖可重试的已登记目标对象和不可重试的未登记/被替换目标，分别确认重试成功与不覆盖且标为未知；另注入复制窗口内源文件仅 mtime 变化，证明目标未发布且旧资产不转成托管资产。本卡的平台结论只适用于实际运行并验证的平台；跨平台链接与 TOCTOU 证据按 [PLATFORM](../../../docs/PLATFORM.md#9-20-agent平台增量) 与 A6 门禁补齐，不因本机用例通过而扩大支持声明。

**停下条件：** 如果需要未冻结的合并优先级，保留冲突项并交复核；不擅自合并不同记录标签。

## A2-04

**连接导入成功项与 AI 建议批次**

- 前置：A2-02。
- 需求索引：R27、R35、R51、R52，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：需设计复核。
- 必读：src-tauri/src/commands/ai_cmd.rs、src-tauri/src/db/ai.rs、src-tauri/src/services/ai_cloud.rs、src/api/ai.ts。
- 允许范围：AI batch 领域 Adapter、操作步骤映射、模型外发摘要与测试；正式标签确认入口保持可信。

1. 只用导入收据中的实际成功/明确纳入的去重资产形成后续集合，不按计数或整个目录推断。
2. 以来源 operation/step 唯一身份取得同一批次；明确纳入重复映射项，冻结服务/模型、压缩图像和视频帧策略、分类上下文、请求次数及 3600 秒运行预算，并遵守现有连接限流。密钥不进入快照。
3. 复用 `tagging.prepare/submit` 与可信 GUI `plans.approve`。批准后 submit 只创建 pending 建议批次并原子绑定 operation/step；只有可信 GUI 显式启动该步骤后才联网。批准后的配置或来源变化必须重新审核，旧 `ai_start_batch(batchId)` 不得绕过审批。
4. 每次网络发送（含本地模型恢复请求）前持久扣减计划请求预算；连接限流等待和单次请求超时均不能超过批准时长剩余值；恢复沿用首次 GUI 启动时写入的持久截止点。模型仅可写入仍处于 pending 的建议；用户确认/拒绝与模型回包竞争时保留用户决策。取消将 operation/step/link 记为 cancelled，未完成建议仍为 pending，后续执行须重新准备范围并单独批准。测试批次创建回传丢失、重复来源/重复纳入选择冲突、限流排队/请求时长与请求预算上限、429、中断、取消终态及用户后续编辑。

**验收与交付：** 批次、建议和 operation/step 来源绑定同事务；响应丢失及同源重试不重复批次/建议；不同重复纳入选择冲突；未导入成功文件不进入批次；批准前及 submit 后未显式 GUI 启动均无网络请求；配置变化使计划失效；请求次数、限流等待与请求时长上限、429、中断和恢复均保留 pending 与已消耗预算；取消的 operation/step/link 状态为 cancelled；迟到模型结果不能覆盖已确认/拒绝或未提交的用户编辑；供应商失败只记录错误并保留建议 pending，不得清空正在编辑的描述；限量范围完成后，剩余素材保持 pending 且可通过新计划单独批准续跑；未经可信确认不写正式标签；视觉输入仍经 imaging。当前无 Pi/MCP dispatcher 的完整实现不阻止本卡验证 services 领域接口，但不得将未来能力声明为已接通。

**停下条件：** 任何步骤从聊天摘要猜测对象或自动确认标签时，停止接入并修正。

## A2-05

**重构独立入库为可复用工作台**

- 前置：A2-03、A2-04。
- 需求索引：R18、R19、R20、R22、R23、R24，含义见 [13](../13-requirements-traceability.md)。
- 复核级别：普通复核。
- 必读：src/pages/ImportPage.tsx、src/components/import/PendingList.tsx、src/components/import/RenameBuilder.tsx、src/stores/taskStore.ts、src/api/import.ts。
- 允许范围：入库页、复用组件/hooks/API/store 与组件测试；为封闭直写入口或接续队列副作用可改对应 commands/services 与定向测试；保留既有独立页面，不做助手布局。

1. 将页面本地领域状态迁到 A1-06 草稿投影，草稿仅持久化固定计划/操作引用与幂等键，不保存本地路径；恢复时按自有计划重建清单和展示路径。保留文件选择、目录授权、分库、改名、异常、取消、逐项失败详情与结果。
2. 提交前持久化幂等键；响应丢失后以同一计划/键收敛到原 operation，结果不确定时保留草稿并禁止换键。交接区分尚未提交计划与已受理操作，只添加引用、不自动提交、扫描或重新入库；取消/恢复绑定准确 operation。
3. 建立单一 WebView 拖拽分派接点，页面挂载只替换活动回调、卸载清理回调且不重复监听；无 AI 时仍可完成手动流程。

**验收与交付：** 组件及服务测试证明切页/重启后从草稿恢复清单、路径或扫描错误文本不进入持久草稿、来源失效时错误可见且不能新提交、保留不确定受理幂等键时仍能同键核对既有 operation、响应不确定后不重复受理、明确未受理的计划拒绝可重准备、交接不重建计划/提交/重新入库、持久结果能区分新入库/重复映射/失败并显示逐项异常、结果查询通过 `spawn_blocking` 执行、只在数据库锁内读取快照并按线性时间映射计划显示名、页面切换不重复安装监听且应用卸载释放监听、准备按准确 taskId 取消、运行取消/恢复按准确 operation、导入成功后色板补算仍接通；原有入库体验可回归。旧直写 `import_files` IPC 不得绕开固定计划受理链路。

**停下条件：** 只复制 ImportPage 到另一个页面导致两份状态或缺失异常详情时不通过。
