# 助手交互原型（A0-06）

问题：切换页面/对话时能否保留独立工作，右侧审核加宽时聊天是否仍可使用？
原型只保存内存状态；演示照片只使用文件名，不读取内容、不上传、不连接数据库或模型。
使用现有 theme.css 语义变量及应用 Logo。它用于确认交互，不能直接作为生产安全实现。

从仓库根执行 `node prototypes/assistant-ui/build.mjs`，双击生成的
`artifacts/assistant-ui/prototype.html` 即可使用。可选执行
`node prototypes/assistant-ui/serve.mjs`，打开终端输出的本机地址。
“演示路径与当前状态”提供四组逐步演示和状态投影；“全窗口验证”隐藏实验控制区。
刷新会重置所有状态。

Windows 浏览器交互回归可从仓库根执行 `node prototypes/assistant-ui/verify-browser.mjs`。
脚本使用已安装的 Microsoft Edge headless、独立临时 profile 和仅监听 `127.0.0.1` 的服务端，
不增加浏览器依赖；通过真实浏览器鼠标/键盘输入验证首用引导可跳过、会话切换、入库交接、
悬浮助手、任务排队/取消、搜索结果按固定 ID 进入素材库、跨页草稿及 960/1366/1920 布局。
它不验证 Tauri WebView、系统 DPI 或原生中文输入法。

运行 `node prototypes/assistant-ui-tauri/dev.mjs` 可在 Windows 打开同一原型的独立 Tauri WebView。
外壳没有 Rust commands、插件、数据库或文件访问，只显示上述内存原型；独立应用标识为
`org.teacell.prototype.assistantui`，不使用正式应用的数据目录。服务器只监听 `127.0.0.1:14321`，
关闭窗口后 runner 会停止服务器。此入口用于补做 WebView/窗口走查，不是生产应用或安装包。

主要路径：附件→右侧计划→确认；独立入库→交给助手；新旧对话切换；
素材库→悬浮助手→完整页审核；任务排队/取消；双入口标签审核；
设置中隐藏/恢复及同侧前移/后移内置底栏入口，开关悬浮助手。已有会话工作时，交接明确新建对话接收并保留原工作；演示搜索固定ID结果可转入素材库，选中清单显式交给新对话，后续库选择不改写原集合。

实现接入时以会话ID保存草稿/工作台，以操作ID订阅任务；两个导入入口复用一个执行服务。
已受理清单交接只能关联原操作，不能再次导入。批准绑定计划中的服务；切换服务使未批准计划失效。
右栏加宽时按剩余聊天空间收起历史，中央Logo不随两侧按钮数量变化。

当前验证证据唯一见 [项目计划](../../docs/PROJECT_PLAN.md#9-20-agent开发状态)。
浏览器尺寸检查不等于系统DPI、Tauri WebView、原生中文输入法、持久恢复或真实模型验收。
真实文件授权、计划批准、任务恢复必须由Rust执行；此页面按钮中的内存状态不构成权限。
