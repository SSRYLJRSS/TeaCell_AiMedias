# 项目计划

> 更新日期：2026-09-22
>
> 本文档记录当前阶段、交付状态和下一阶段范围。产品行为见 [PRD.md](PRD.md)，技术结构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 项目目标

构建一个能在数万级本地素材上长期使用、维护成本可控的个人素材管理系统：

- 入库可托管、可追踪、可取消。
- 浏览和搜索在大数据量下仍稳定、可解释。
- 标签和 AI 打标形成可治理、可撤销的闭环。
- 删除、移动、导出和备份不产生静默数据风险。
- 代码结构和文档上下文足够稳定，便于持续迭代和 AI 协作。
- 在单一 `main` 上交付 Windows 正式支持与 macOS/Linux 预览支持，不维护长期平台分支。

### 2.2 当前发布阻塞

以下项目完成前，不能把当前版本标记为“可放行”：

1. **真实素材 UAT**：超级搜索 relevance 排序、mustNot 排除、should 全不命中仍保留、位置权重和 hydrate 后 plan JSON 需要真实数据证据。
2. **核心用户旅程**：使用真实素材走通导入、浏览、AI 打标、搜索、查看器、评级、导出、删除恢复和备份恢复。
3. **格式与性能**：在目标机器上复测 RAW/HEIC、视频播放、3 万级搜索和网格滚动。
4. **工作区交付边界**：所有应发布改动必须完成审查、测试并形成可回退提交。
5. **发布门禁**：`scripts/smoke.ps1`、严格 Rust 门禁、前端门禁和人工 UAT 必须全部有结果记录。
6. **三端自动化**：macOS/Linux 编译与测试尚未成为 `main` 合并硬门禁，当前 Windows CI 不能证明三端可用。
7. **三端候选与真机证据**：尚未形成同一提交的三端安装包，也没有 Apple Silicon macOS 与
   Ubuntu 24.04 的核心五步真机记录。

### 2.3 跨平台整合基线

- 当前 `main` 只有 Windows workflow，未自动产出桌面安装包，也没有真实桌面 E2E。
- `wt/three_gogogo` 包含一批已提交的平台路径、凭据和能力门控改动；该工作树另有未提交的 CI、
  候选打包、媒体 sidecar 和相关修复，必须先审查和分批验证，不能整体盲合。
- 两个工作树都有用户未提交修改。开始整合前先建立可恢复快照和清晰交付边界，禁止 reset、
  checkout 或 clean 丢弃现场。
- 在三端门禁与目标真机证据完成前，macOS/Linux 产物只能称为实验构建。

当前项目计划不把“自动化全绿”等同于“产品可发布”。真实素材验收仍是独立门禁。

### 2.4 首发构建目标

三端适配收口后，首发覆盖三个构建目标。三道门分别是：代码门（编译、门禁、三目标 CI code-gate.yml 配置）、构建门（在目标平台产出安装包）、用户验证（真机安装运行）。

状态口径（复查修正）：每格只引用当前工作树可复现的证据，区分「历史构建产物」与「当前 SHA 可复现构建」。三目标 sidecar 的归档/最终 SHA 已填入 manifest；Windows 已通过本机严格校验，并已实际产出 NSIS 与 MSI 安装包（MSI 使用 936 代码页以容纳中文产品名）；Linux/macOS 仍需目标 runner 的运行时复核。候选包（同一 SHA 三目标安装包）尚未由 CI 产出。

| 目标 | 代码门 | 构建门 | 用户验证 |
|---|---|---|---|
| Windows x64 | 本机通过（typecheck/lint/前端三次单测/fmt/clippy/全 Rust 测试/smoke），CI 待运行 | sidecar strict check 已通过；本机 NSIS、MSI bundle 均已通过 | 待用户真机验证 |
| macOS Apple Silicon (aarch64) | 工作流初稿已在树（code-gate 含 native 构建），CI 未运行 | 工作流初稿已在树（release-candidate 含 sidecar 准备 + 硬校验），待 CI 产出 | 待用户真机验证（无真机） |
| Linux x64 | 工作流初稿已在树，CI 未运行 | 工作流初稿已在树，待 CI 产出 | 待用户真机验证（无真机） |

补充：历史 Windows runner 在新版 MSVC 14.51 曾因 `msvc_stl_shim.cpp` 重复声明 `__std_*` 失败；
当前工作树已按 `_MSC_VER < 1945` 门控旧工具链补符号，本机 `cargo check`、clippy 和全量测试均已
复核通过。该修复以及 `macos-15` Apple Silicon runner 标签仍需随下一次真实 GitHub workflow 运行确认。

本版本已取消跨设备素材库迁移，只保留数据库备份/恢复，不再安排 M1–M4 的六向库迁移、迁移包故障注入和迁移 UI。首发不包含 Intel Mac 或其他 Linux 架构。分平台构建入口见 [DEVELOPMENT.md](DEVELOPMENT.md)，分平台运维见 [OPERATIONS.md](OPERATIONS.md)。

## 5. 交付流程

每个功能按以下顺序推进：

1. 确认 PRD 和协议，不接受口头隐含需求。
2. 写清验收标准、失败路径和数据不变量。
3. 实现代码和测试。
4. 跑定向测试与完整门禁。
5. 真实桌面环境走查。
6. 更新权威文档、版本和发布说明。
7. 形成可独立回退的提交。

## 6. 质量目标

| 维度 | 目标 |
|---|---|
| 正确性 | 数据层、文件系统和 UI 状态保持一致 |
| 稳定性 | 长任务可取消/恢复；重启不留下永久 processing |
| 性能 | 3 万素材可浏览；搜索目标 ≤500ms；图像解码有限流 |
| 安全 | 本地优先、凭据进 keyring、路径防穿越、SQL 参数绑定 |
| 可维护性 | commands/services/db 分层；契约集中；无历史文档冲突 |
| 可交付性 | smoke、Rust/前端门禁、真实 UAT 全部可复验 |

## 7. 风险登记

| 风险 | 影响 | 控制 |
|---|---|---|
| 真实素材样本不足 | 自动化通过但产品语义未验收 | 把真实 UAT 作为独立发布门禁 |
| 搜索协议多入口漂移 | 列表、总数、诊断结果不一致 | SearchPlanV3 作为唯一执行计划 |
| 分面双事实源 | AI、手工和筛选结果不同步 | tag_facets 唯一事实源 |
| 长任务和脏工作区 | 出错后难以回滚 | 小批提交、幂等迁移、备份保底 |
| RAW/HEIC 许可和分发 | 对外发布存在合规风险 | 分发前法务复核并保留替换方案 |
| 本地模型环境差异 | 安装成功但推理不可用 | 检测、就绪复检、推荐模型和错误引导 |
| 大组件持续膨胀 | 修改风险和维护成本增加 | 独立治理批次拆分，不与功能混改 |
| 缺少 macOS/Linux 本机 | CI 通过但桌面行为仍不可用 | 候选版由目标平台测试者执行固定五步脚本 |
| 长期平台分支漂移 | 同一功能形成三套实现和发布历史 | 单一 `main`、短功能分支、平台能力层和三端门禁 |
| GPL sidecar 许可材料不完整 | 安装包可运行但分发不合规 | 每目标 manifest 固定来源/hash，严格门禁要求许可证材料和发布前复核 |
