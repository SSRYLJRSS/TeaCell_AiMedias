## 1. 总则

### 1.1 测试目标

本文要回答的不是"代码能不能跑、有没有 bug"，而是一个问题：

**站在一个第一次拿到这个软件的真实用户角度——这个软件，我敢不敢用它管我几万张吃饭的素材库？**

具体拆为三问（即老板定的三类核心问题，本文所有用例均标注类别）：

### 1.2 三类核心问题定义与判定口径

**A 类：UI 界面是否存在重复或冗余**
- 同一动作存在多个入口，但行为、文案、二次确认不一致（网格删除按钮 vs 右键删除 vs 快捷键）
- 同一信息重复展示（清单页与确认页重复展示相同统计）
- 完成一个用户意图所需操作超过必要步骤（给一张图打一个标签超过 3 次点击）
- 术语不统一：素材/文件/图片混用、标签/分面混用、"删除/移除"混用
- 视觉噪声：无信息量的图标、分隔线、装饰元素、过度留白

**B 类：各功能逻辑是否存在冲突或隐患**
- 跨模块状态不同步（AI 采纳了标签，但标签树计数没变）
- 边界条件错误（数值分面排序按字符串排：2 排在 10 后面）
- 并发/时序冲突（AI 打标批次进行中删除该素材；打标进行中恢复备份）
- 状态机泄漏（取消批次后状态仍停在 processing；建议拒绝后又冒出来）
- 规则冲突未被系统拦截（跨分面合并标签；同值条件同时进必须区与排除区）

**C 类：代码看似可行但实际不可用（最阴险，单测全绿但用户手上废掉）**
- 成功是假的：导出 move 完成提示成功，但库记录仍指向旧路径，查看器点开死链
- 失败被吞：删除文件失败（只读/被占用），但素材从列表里消失了（假删除），文件还在磁盘
- 功能存在但等于没有：入口存在但点击无响应；关键参数藏得太深没人找得到
- 长任务无反馈：1000 张导入中界面无任何进度变化，用户以为死机直接强杀
- 提示不可行动：报错只有裸 error code，用户不知道下一步该干嘛

### 1.3 方法论框架（四层，检索最佳实践后融合）

| 层 | 方法 | 用在哪 |
|---|---|---|
| 用例设计 | ISTQB 等价类划分 / 边界值分析 / 判定表 / 状态迁移 | 各模块用例表（每条注明用了什么技术） |
| 可用性检查 | Nielsen 十大可用性启发式（0-4 严重度评级） | 模块 B：UI 逐屏走查 |
| 场景验收 | UAT 用户旅程（导入→打标→搜索→导出主链路闭环） | 模块 L：联动矩阵 |
| 探索测试 | SBTM 章程驱动 + Tour 巡游 + PROOF 汇报格式 | 第 15 章探索性测试 |

### 1.4 缺陷严重度与用例优先级

**缺陷严重度**：

| 级 | 定义 | 处理要求 |
|---|---|---|
| P0 | 崩溃 / 数据丢失 / 核心功能完全不可用 | 阻塞发布，当天修 |
| P1 | 主流程受阻，有绕行方案 | 发布前必修 |
| P2 | 次要功能缺陷、明显体验问题 | 排期修 |
| P3 | 文案、轻微 UI 瑕疵 | 记录即可 |

**用例优先级**：P0=必测且必须通过；P1=必测；P2=时间允许测；P3=顺带记录。

### 1.5 通过标准与质量评级

| 评级 | 结论 | 判定 |
|---|---|---|
| A | 可发布 | P0=0，P1≤3 且均有绕行方案，P0 级用例通过率 100% |
| B | 修复后可发布 | P0=0，P1 4~8 个 |
| C | 需再一轮测试 | 出现 P0，或 P1>8 |
| D | 阻塞 | P0≥3，或出现任何数据丢失类缺陷 |

### 1.6 执行纪律（硬约束）

1. **执行即记录**：每个用例当场标 ✅/⚠️/❌，禁止事后凭记忆补记
2. **先固定复现**：缺陷需连续复现 2 次才入库；复现不了的记"偶发"并留录屏
3. **截图/录屏命名**：`{模块}-{用例号}-{序号}.png`（如 `SS-C03-1.png`），与缺陷记录一一对应
4. **模块小结**：每完成一个模块花 5 分钟小结（缺陷数、有无拦路问题、是否继续）
5. **防误报**：不确定"是不是缺陷"时，先查 5.5 节负向范围与契约文档；仍不确定就记录并标"待判定"
6. 每轮测试开始前重置测试库，保证用例前置条件干净

### 2.5 三端核心五步闭环（X-01 ~ X-06）

每个候选版本必须分别在 Windows 10/11 x64、Apple Silicon macOS 和 Ubuntu 24.04 x64 的目标设备上
用实际安装包验证。只在知情测试者的独立测试库和素材副本中操作；第一阶段不把另一系统的数据库或
素材库复制过来。记录应用版本、Git 提交、系统版本、CPU 架构、安装包文件名与 SHA256、素材包版本、
执行人和结果。不得把 CI 编译结果记作真机 UAT。

| 编号 | 操作 | 通过标准 |
|---|---|---|
| X-01 安装与启动 | 安装候选包并启动应用；macOS 若出现 Gatekeeper 提示，按知情测试包说明处理 | 主窗口正常显示，无白屏或启动崩溃；记录安装/首次启动问题，未签名或未公证包只用于知情测试 |
| X-02 导入 | 从 S1 复制一组 JPG/PNG，包含中文、空格、emoji 文件名和嵌套目录，导入测试库 | 清单、确认、进度和完成数量一致；不支持的路径有导入前警告；原始样本保持不动 |
| X-03 浏览与搜索 | 浏览刚导入的素材，分别按文件名片段和已知标签搜索 | 缩略图、计数、路径显示和搜索结果相符；空结果和恢复条件可理解 |
| X-04 查看 | 打开图片；如 S1 附有短视频，再打开并播放/生成代理；前后切换并关闭查看器 | 图片可查看；视频在该平台能播放或给出明确可行动的兼容性提示；Linux 默认代理为 VP8/WebM，不得把 H.264 当硬要求 |
| X-05 导出 | 复制导出本轮选中的素材到一个新的空目录，核对数量并打开输出文件 | 导出清单与文件数一致、内容可打开；源文件仍在原位置；应用不报告假成功 |
| X-06 平台能力 | 查看本地模型/AI 设置，并尝试配置一个外部兼容服务（无真实密钥时只检查入口） | Windows 托管 Ollama 可用范围符合当前能力；macOS/Linux 不显示托管安装/启动入口，外部兼容 AI 连接仍可配置；不支持命令不启动后台进程 |

X-01~X-05 任一失败，该平台当前版本不得标记为预览或正式支持；X-06 出现假入口、误启动托管能力、
静默降级或错误结果同样阻止该平台交付。每个失败都按第 16 节记录最小复现、截图/脱敏日志和包 SHA256；
修复后必须对同一候选提交重新跑完整五步，不能只复测失败单步。

## 3. 模块 A：导入功能

**测试角度**：
1. 流程完整性——两段式入库（清单确认 → 改名模板构造器）每一步可理解、可回退、可取消
2. 异常韧性——坏文件不得连累好文件；失败必须可见且可读
3. 数据一致性——导入中途取消/强杀进程后，库自洽（无半条记录、无孤儿缩略图任务）
4. 体感——大批量导入时界面是"活着"的（短锁设计约束验证）

**前置条件**：全新测试库（按 2.2 重置）；S1~S5 素材包就绪。

| 编号 | 测试要点 | 验证方法（操作步骤） | 预期结果 | 类别 | 级 |
|---|---|---|---|---|---|
| A-01 | 空库首次引导 | 全新库首次启动，进入素材库页 | 空态不白屏，有明确引导入口，文案与实际导入入口一致，点击直达导入页 | C | P0 |
| A-02 | 文件夹递归导入 | 拖入含 3 层子目录的文件夹 | 清单包含全部子目录文件，路径展示正确，计数与磁盘实际一致 | F | P0 |
| A-03 | 单文件/多文件拖入 | 分别拖 1 个文件、拖 20 个散文件 | 均进入清单确认；散文件不丢、不重 | F | P0 |
| A-04 | 两段式流程完整性 | 走完 拖入→清单确认→改名模板→入库 全程；中途分别点返回/取消 | 每步可回退；取消后库无残留记录；确认页统计（数量/大小）与清单一致 | B | P0 |
| A-05 | 改名模板构造器 | 构造含 序号/日期/原文件名 的模板；构造会产生同名冲突的模板 | 预览实时更新；模板保证唯一文件名；纯中文模板名可用 | B | P1 |
| A-06 | 重复导入识别 | 同一文件夹导入两次；同一文件拖两次 | 第二次被识别为已入库（提示跳过/重复计数），不产生重复记录；同源文件正确归组而非重复 | B | P0 |
| A-07 | 损坏文件失败明细 | 导入 S4 中的截断 JPG 与 0 字节文件 | 失败明细页展示，失败原因是可读、可行动的说明而非裸错误码或堆栈；失败文件不入库；好文件正常入库不受连累 | C | P0 |
| A-08 | 伪装扩展名 | 导入 txt 改名的 .jpg | 识别为不可用并计入失败明细，不崩溃、不生成黑图缩略图 | B | P1 |
| A-09 | HEIC 解码 | 导入 S2 中的 HEIC 文件 | 目标原生 HEIF 静态库链路成功生成缩略图，查看器可打开 | F | P0 |
| A-10 | 中文/特殊字符/超长文件名 | 导入 S4：纯中文名、含空格/#/%/括号/emoji、255 字符长名 | 入库、缩略图、搜索、导出全链路无乱码无失败（边界值+特殊字符等价类） | B | P0 |
| A-11 | 导入中途取消 | 大文件夹导入进行中点取消 | 已完成部分状态一致保留；未完成部分无半条记录；可再次发起导入 | B | P1 |
| A-12 | 大批量导入体感 | 导入 S3（≥1000 文件），同时切到素材库页滚动浏览 | 进度持续更新；UI 不冻结；缩略图渐进出现（短锁验证——导入不阻塞浏览） | C | P0 |
| A-13 | 双层缩略图 | 导入完成后立即快速滚动网格 | 先占位图后高清异步加载，滚动不错位不闪烁（LRU 生效） | C | P1 |
| A-14 | 导入中断恢复 | 导入进行中直接强杀进程，重启应用 | 库自洽：无孤儿记录、无死缩略图任务、可继续导入 | B | P1 |
| A-15 | 同源文件组归组 | 导入 S5（同图不同尺寸、相同副本不同目录） | 按设计识别为同源文件组并归组展示（与模块 J 联动复验） | B | P1 |
| A-16 | 导入页 UI 一致性 | 走查清单列、排序、批量勾选、按钮文案 | 文案术语与其他页统一（"素材"vs"文件"不得混用）；勾选逻辑与其他页一致 | A | P2 |
| A-17 | 万级库 soak | 将 S3 压力包复制扩充至 ≥10000 文件导入，随后浏览、搜索、查看器轮流操作一遍，应用不退出并搁置过夜 | 次日验收：无崩溃、无私有内存或句柄持续膨胀（任务管理器对照启动值）、核心操作体感无明显劣化；素材拷贝耗时大，可与准备阶段其他任务并行 | B | P1 |

**重点盯防**：空库引导必须直达实际导入入口；导入失败原因必须可读、可行动。中断恢复（A-14）涉及数据一致性，必测。

**限定范围进度补充**：AI 打标选“仅前 N 张”时，进度条分母显示本次后端实际待执行数量；批次总量和累计处理数单独展示。以 205 项批次选前 10 项为例，本次执行应为 `0/10 → 10/10`，批次累计应保留 `10/205`；再次启动前 10 项后，本次重新从 0 计数，批次累计不能倒退。切换批次、迟到事件、取消与失败不能串用其他批次的计数。

## 4. 模块 B：UI 界面（含冗余专项）

**测试角度**：
1. 可用性底线——Nielsen 十大启发式逐屏过一遍
2. 冗余猎杀——专找重复入口、重复信息、多余步骤、术语不一致
3. 规范符合性——`docs/UI_DESIGN_SYSTEM.md` 硬约束逐条对

**走查范围**：五页面（ImportPage / LibraryPage / AiTaggingPage / SuperSearchPage / SettingsPage）+ 查看器 + 全部弹窗（导入确认、备份恢复、彻底删除确认、高级浮层、标签值 portal 浮层）。

### 4.1 Nielsen 十大启发式逐屏走查（U-01 ~ U-10）

| 编号 | 启发式 | 本项目具体检查点 | 验证方法 | 预期结果 | 级 |
|---|---|---|---|---|---|

## 5. 模块 C：超级搜索功能

**测试角度**：

- **K-09 缺陷归属**：K 用例发现的问题走标准缺陷模板（类别 = F），但严重度按「对可维护性的长期风险」评估，不一刀切按 P0/P1 卡死发布——历史债务不该阻塞功能发布。K 结论在测试报告中单独成节：**代码健康度**（见第 17 章）。

## 17. 测试报告产出要求（测试结束后的交付物）

报告结构（按测试报告最佳实践）：

3. **缺陷分析**：
   - 严重度分布表（P0~P3 × 数量 × 状态）
   - 模块分布热力（哪个模块缺陷最密集）
   - **三类核心问题专项结论**：A 类 / B 类 / C 类各一段（数量、典型代表、系统性风险判断）
   - **代码健康度（模块 K 专项结论）**：K-0 各静态基线数对照（clippy / fmt / unwrap 等是否恶化）、K-01~K-08 逐条结论与观察项、代码债务是否阻塞发布的判断
4. **遗留风险与高风险回归核对**：附录 B 逐项记录当前结果（通过/失败/未执行）
5. **上线建议**：放行 / 有条件放行（附条件清单）/ 阻塞（附阻塞项）
