# UI 视觉与交互规范

> 更新日期：2026-09-17
>
> 本文档是前端视觉和交互的唯一规范来源。令牌实际值定义在 `src/styles/theme.css`，基础类定义在 `src/styles/index.css`。

## 1. 设计目标

茶馆AI素材管理是素材管理和 AI 打标工作台。界面应保持安静、克制、专业，让图片、视频和标签成为视觉中心。

核心气质：

- 暖灰画廊背景。
- 墨黑主操作。
- 低饱和状态色。
- 高信息密度但不拥挤。
- 明确层级，减少装饰。

不采用：

- 大面积鲜艳渐变。
- 后台模板式卡片堆叠。
- 过圆、过重阴影和玻璃拟态。
- 为普通操作添加大面积红色或状态色。
- 用装饰元素填补空白。

## 2. 主题令牌

业务组件只使用语义令牌，不硬编码颜色。

| 令牌 | 用途 |
|---|---|
| `--color-bg` | 页面基础背景 |
| `--color-surface` | 次级区域、安静选中背景 |
| `--color-surface-raised` | 输入框、弹层和抬升表面 |
| `--color-surface-hover` | 列表悬停和明确选中 |
| `--color-border` | 普通边框和分隔 |
| `--color-border-strong` | 强边界和交互边界 |
| `--color-hairline` | 极细分隔 |
| `--color-text` | 主要信息 |
| `--color-text-secondary` | 说明、日期、计数 |
| `--color-text-tertiary` | 占位和最低优先级内容 |
| `--color-accent` | 主操作和核心强调 |
| `--color-status` | 当前项、待确认、进度小面积强调 |
| `--color-success` | 成功和完成状态 |
| `--color-danger` | 删除、失败和不可逆风险 |
| `--radius-control` | 控件圆角 |
| `--radius-item` | 列表项和导航项圆角 |

主题支持 `light`、`dark` 和 `system`。组件不得根据主题复制结构，只切换令牌。

## 3. 字体与信息层级

- 字体优先 `Segoe UI`、`Microsoft YaHei UI`。
- 根字号 15px，普通正文约 13px。
- 辅助信息约 11 至 12px，只用于日期、数量和状态说明。
- 正文默认 400，区块标题和选中项使用 600。
- 不全局启用灰色抗锯齿，保证 Windows WebView2 中文清晰度。
- 不使用负字距。

层级顺序：

```text
页面标题/关键状态
  -> 区块标题
    -> 内容
      -> 辅助信息
```

区块标题统一使用 `.ui-section-title`。不要为每个区块创建带边框和阴影的卡片。

## 4. 间距与几何

- 页面主要区块间距：16px。
- 区块内部间距：12px。
- 紧凑列表行高：32 至 36px。
- 图片管理侧栏宽度：约 224px。
- 打标控制栏宽度：约 252px。
- 控件圆角使用 `--radius-control`。
- 列表项圆角使用 `--radius-item`。
- 主按钮不使用胶囊形；标签和状态角标可使用胶囊。
- 阴影只用于抬升工具栏、菜单和弹层。

固定尺寸控件应设置稳定宽高或最小尺寸，避免 hover、加载和动态文案引起布局跳动。

## 5. 页面布局

### 5.1 全局

- 顶部为三端统一的无边框自绘 TitleBar；窗口控制通过 Tauri 窗口 API 操作。平台能力不得把自绘按钮报告成系统原生按钮；原生装饰若将来启用，必须与目标专属 Tauri 配置和 TitleBar 条件渲染同批修改、同批验证。
- 底部主导航为入库、素材库、打标。
- 查看器打开时隐藏全局底栏，避免双重导航。
- 主内容区不允许被固定栏遮挡。

### 5.2 入库

- 待入库统计、分库/改名选项和入库动作集中在左侧任务栏。
- 待入库数量与大小只在左侧清单摘要展示；右侧清单工具栏不重复显示同一统计。
- 入库进行中，阶段、整体进度与当前文件在左侧任务栏内集中展示。扫描阶段显示已发现数量，其他已知总量阶段显示 `当前/总数`。
- 成功/重复/失败只在后端已产生有效结果后显示，完成前不得用 `0` 冒充实时结果；完成后保留最终计数。
- 进度区固定在左侧任务栏底部，动作按钮在进度区上方；按钮出现或消失不得推动进度区。
- 入库完成后保留最终进度，直到下一次新入库开始；不得自动消失或重置为空闲态。
- 入库页不得在底栏上方重复绘制入库进度；离开入库页后，全局任务层可继续显示运行中的后台入库任务。
- 扫描完成后，无法解析入库缩略图的图片须在单独确认层明确列出，确认后只能移除这些文件、不能把它们加入待入库队列；可生成占位预览但高清/元数据链路可能受限的格式须在预览和待入库清单持续显示限制提示。
- 完成结果不在右侧再复制一份；右侧只保留可展开的失败明细。

### 5.3 素材库

- 左侧为类型和标签区域。
- 主区为虚拟网格。
- 顶部工具栏承载搜索、排序、计数和选中操作。
- 批量操作只在选择存在时显示或启用。
- 右键菜单使用统一 `ContextMenu`，点击外部关闭且不得拦截菜单内部事件。
- “智能标签”和“文件属性”中的分面分组默认收起，用户可按分组展开或使用全部展开/收起；折叠状态不改变筛选条件。

### 5.4 超级搜索

- 搜索输入是第一视觉焦点。
- 必须、优先、排除三区语义清晰，不能通过颜色单独区分。
- 宽屏条件面板使用等宽、等高的三栏；窗口不足以容纳完整条件行时改用“必须 / 优先 / 排除”页签，不压缩控件。
- 条件行分为“字段与行操作”以及“运算符与条件值”两层，字段、值和删除/移动操作不得在窄列中互相覆盖。
- 手动筛选只保留三个平铺条件区，不提供条件组入口；后端仍保留 QueryExpr 对 AI/历史计划的执行兼容，已有嵌套结构由搜索链原样执行。
- 优先区顺序即优先级，提供序号和明确的上移/下移及菜单排序；UI 不展示权重，也不保留没有可靠交互的拖拽手柄。
- 图片尺寸筛选使用独立的“宽度（px）”与“高度（px）”字段；后端兼容的总像素数字段不作为手动字段入口。宽高比使用预设或“宽:高”自定义输入，二者不同时展开。
- 颜色筛选使用色点和中文颜色名的列表；色相、饱和度、明度等算法维度仅供结果卡片和历史/AI 条件兼容，不作为普通用户的手动入口。
- 字段选择器的“最近使用”只保留去重后的最近 3 个字段，作为快捷入口但不替代原分组；内部 MIME、编解码、原始坐标及算法/专业技术字段不进入普通手动入口，历史/AI 条件仍按协议兼容。
- 条件摘要只在页面摘要区出现一次，条件构建器内部不重复绘制另一条“预览”句。
- 普通条件使用透明/抬升表面建立层级，不用常驻灰色填充块；灰色只用于辅助、悬停或禁用状态。
- 警告、诊断和有效条件同时存在时，用户能看懂哪条被忽略以及为什么。
- 不保留已明确不做的旧控件，避免“看似可用实际无效”。

### 5.5 打标工作台

固定阅读顺序：

```text
主图 -> 缩略图轨道 -> EXIF/状态 -> 标签编辑 -> 确认操作
```

- 主图使用剩余空间并保持视觉中心，但不得挤占标签编辑与确认操作的可用高度。
- 标签编辑区优先保留充足高度；窗口变矮时先缩小主图，标签滚动区与确认栏保持可见。
- 当前缩略图使用深色边框和小状态点。
- 分面名称固定宽度，标签内容自适应。
- “确认写入”是单张主操作。
- “拒绝”使用次按钮，默认不是大面积红色。
- 已确认状态用文字表达，不伪装为按钮。
- 不提供“AI 打标/手动模式”切换；AI 建议与手工填写共用同一套分面和确认流程。
- 打标页的模型选择只切换当前用途绑定，不在页面内维护第二套激活档案。
- 打标页左栏不重复页面名称；顶部先呈现当前服务上下文与批次操作，再依次呈现当前模型、当前批次和历史批次。

### 5.6 设置页

- 左侧为分组导航，右侧为当前分组。
- 设置页的偏好项在值改变后自动保存，并在内容区顶部显示等待、保存中、成功或失败状态；初始加载、悬停和聚焦不得触发写入。页面不提供通用“保存设置”按钮；需要确认的独立新增、编辑或危险操作仍在其操作区域内明确提交。
- 本地模型安装、拉取和运行状态必须可区分。
- Ollama 向导选中的模型必须写入实际 AI 服务连接；若打标用途尚未绑定有效连接，才默认补绑该本机连接，不覆盖用户已有的有效用途选择。外部兼容 AI 服务与托管 Ollama 必须分区管理；非 Windows 不显示应用托管安装、启动、模型列表等入口，也不得在界面挂载时探测这些能力。
- 在线服务编辑器可设置最大并发、RPM 与每小时请求上限；留空或 0 显示为“不限”。连接列表应展示当前上限，限流提示需说明打标与 AI 搜索共享连接额度及 429 会停止当前批次。
- 在线服务编辑表单按“服务名称 → API 格式 → 服务地址 → API 密钥 → 模型名称”呈现；API 格式、地址和凭据属于主要配置，高级设置只收纳并发与频率上限。连接状态与测试动作放在表单底部。作者推荐使用轻量下拉预设；表单不使用整块灰色背景。
- AI 分类设置只呈现可编辑的分类说明；系统提示词和搜索机器协议由应用维护，不提供可覆盖它们的全局文本框。分类列表、说明及显式数量/数值配置共同构成用户能调整的分类业务规则。
- 模型列表属于当前服务配置。协议、地址、密钥或连接档案变化时清空旧列表并作废在途响应；没有可用密钥时模型仍可手动输入，但远端发现入口应禁用。
- 首次启动提示查看新手教程；选择查看或暂不查看后记录一次，旧配置缺少字段时默认未处理。调用系统默认浏览器失败时在同一对话框展示可复制地址；标记保存失败时允许继续使用并如实提示。
- 素材卡片默认比例为 4:3，读取时保留已保存的合法比例。主色色条总开关控制全局显示，库卡片和大图浏览开关各自选择显示位置；说明须明确主开关不删除色板数据。
- 数据目录、日志、缓存和备份恢复显示真实路径与结果。

#### 5.6.1 设置页专用视觉规范

设置页以“低装饰的系统表单”为基准，所有设置分组必须遵循同一套结构：

```text
页面内容区
  -> 页面标题 + 简短说明
    -> 分组标题
      -> 一级描边容器
        -> 连续设置行 / 分区标题行
```

当前标准导航顺序为“素材库与入库、AI 与模型、标签与分类、外观与浏览、存储与维护、诊断与支持、关于”。“AI 与模型”下仅保留服务管理、超级搜索、自动打标三个用途子页；“关于”承载应用版本、项目、许可证和作者主页，日志、诊断包和反馈统一归入“诊断与支持”。

超级搜索用途设置无单独绑定时显示“自动选择在线服务”，并从后端读取真实解析结果；旧版默认档案不得作为实际服务展示。连接不可用时直接展示可执行原因。用户仍可显式选择已启用的本机连接，禁用连接不可新选。

- 右侧内容区最大宽度为 `1040px`，页面内边距为 `24px`，一级分组间距为 `24px`。
- 分组标题位于容器外，使用辅助文字色和小号字；标题不放进卡片头部，不另加背景。
- 每个分组只允许一个一级描边容器。容器使用页面背景，不增加常驻填充色、阴影或第二层外框。
- 普通设置项使用连续行组织，行与行之间只用 `--color-border` 分隔；不得把每一项做成独立圆角卡片。
- 标准设置行在宽屏为左右两列：左侧名称与说明，右侧控件或操作；窄屏改为上下排列。标准内边距为横向 `16px`、纵向 `12px`。
- 需要在同一分组内继续分区时，使用“分区标题行 + 连续内容行”。分区标题行可以包含名称、简短说明和一个右侧动作，但不得形成嵌套卡片。
- 普通内容默认透明背景。`--color-surface` / `--color-surface-hover` 只用于导航选中、悬停、禁用提示或明确状态，不用于给整块普通设置内容铺底色。
- 标识、类型、规则摘要等元信息优先使用次级文字和间距建立层级；只有真正的状态标签才使用带底色角标。
- 同一行有多个轻量操作时使用文字按钮并保持稳定间距；该区域的主操作才使用实心按钮，删除等危险操作使用危险态。
- 拖拽设置项必须同时提供可理解的手柄提示；拖拽中使用透明度与文字/光标变化表达，不只依赖颜色。
- 加载、成功、错误和空态放在对应分区内，并占用稳定行空间；不得临时在一级容器外再生成提示卡片。

“标签与分类”属于密集设置页，额外遵循：页面说明与“AI 自动打标分类、手工填写分类、已停用的分类”标题置于描边容器外；容器只承载分类行和行间分隔线。五个内置 AI 分类可编辑说明和显式规则、可停用/恢复但不可删除或移出 AI 组；用户创建的分类可编辑、停用/恢复和删除。画面摘要以固定、不可操作的协议行展示；内部兼容 key 不显示。英文标识、系统属性和选择规则作为次级元信息展示，不使用独立背景色卡片；“分类设置、分类标签、画面摘要”等重复说明标题不再单独占用容器内空间。

“存储与维护 → 危险操作”遵循可逆性分层：

- “素材库记录”只清数据库记录、搜索索引和派生缓存，默认不触碰原始图片/视频。
- “原始素材文件”必须单独列出并使用危险色提示；它会永久删除磁盘文件，成功项同步移除记录，失败项保留记录供重试。
- 导出任务、搜索条件、诊断日志可独立清理；全选明确标注为“恢复出厂设置”，并要求再次确认。
- Ollama 模型和安装包不放进全选范围；模型可能由其他应用共享，模型空间在“AI 与模型 → 服务管理”单独管理，安装包在“缓存管理”单独清理。

### 5.7 查看器

- 媒体占主要空间，不透明背景。
- 底部信息栏、标签栏和胶片条按稳定顺序布局。
- 缩放和拖拽使用 transform，避免每帧触发布局。
- 视频使用自定义控件时保持键盘焦点和 aria 语义。

## 6. 控件

### 6.1 按钮

- 主按钮：深色实心，只用于当前区域最重要动作。
- 次按钮：透明或浅背景，用于取消、刷新、拒绝和恢复。
- 危险按钮：只用于不可逆动作，默认避免大面积红色。
- 图标按钮优先使用 lucide 图标，必须有 tooltip 和可访问名称。
- 不用带文字的圆角矩形代替本应使用图标的工具操作。

### 6.2 输入

- 输入框和下拉框使用 `.ui-control`。
- Focus 状态必须可见，不得移除键盘焦点反馈。
- 数值输入明确单位、范围和非法值反馈。
- 搜索输入需要防抖，但不能因防抖造成重复提交或旧响应覆盖。

### 6.3 选择与开关

- 二元设置用 switch/checkbox。
- 少量互斥模式用 segmented control。
- 多选项使用列表或 chips，不用多个并排大按钮。
- 模式选择必须有文字，不仅靠图标。

### 6.4 菜单与弹层

- 菜单项点击后关闭，除非操作需要连续执行。
- 危险项与普通项视觉分离。
- 弹层内不创建第二套主导航。
- 不允许在卡片内继续嵌套卡片作为信息层级。

## 7. 状态表达

每个交互状态至少具备两种表达方式：

- 选中：背景/线条 + 文字权重或图标。
- 禁用：透明度 + cursor + 说明。
- 错误：危险色 + 明确文案 + 恢复动作。
- 加载：稳定占位或进度 + 当前阶段。
- 完成：状态文字或图标，不伪造仍可点击的按钮。

禁止：

- 只靠颜色表达选中或错误。
- 失败后保持成功态。
- 将不确定进度伪装成百分比。
- 用无限动画掩盖无反馈的长任务。

## 8. 响应式

主要检查宽度：

- 1920px
- 1366px
- 1024px 或系统最小窗口附近

要求：

- 文本不重叠、不截断关键信息。
- 工具栏空间不足时优先换行或收进菜单。
- 主内容不因侧栏收缩而失去可用空间。
- 固定格式元素使用宽高约束，避免 hover/loading 导致布局跳动。
- 小窗口不允许用缩小正文解决空间不足。

## 9. 可访问性

- 所有交互元素可通过键盘到达。
- 图标按钮有 `aria-label` 或可理解文本。
- Dialog 打开后焦点进入，关闭后返回触发点。
- 表格/列表操作具备明确角色或语义。
- 键盘快捷键不得抢输入框焦点。
- 动画尊重 `prefers-reduced-motion`。

## 10. 开发约束

1. 先复用主题令牌和基础类，再增加局部样式。
2. 同一语义状态不得在不同页面使用不同颜色。
3. UI 改动不改变业务数据流。
4. 结构重排通过组合组件完成，不复制现有组件。
5. 新组件必须有测试或明确的手工验收路径。
6. 删除控件时同步删除契约、测试和无入口残留。
7. 不把功能说明文字直接铺在应用界面中，使用 tooltip、空态或必要帮助入口。
8. 任何新页面都要检查 light、dark、1366px、1920px 和键盘操作。
